## 项目简介

Study Tracker 是一个面向考研学生的学习规划 Web 应用，围绕**刷题、错题整理、背书复习**三大核心任务展开，并提供自习室协作与 AI 学习助手。

自己是考研人，最初就是为了记自己的刷题进度、攒错题、排背书计划写的，身边同学用着顺手，就一点点打磨成了现在的样子。前端为原生 HTML/CSS/JavaScript，不依赖任何框架或构建工具；后端基于 Node.js + SQLite，支持 PWA 离线使用与多设备数据同步。

## 核心功能

### 学习任务管理

- **刷题本**：习题册（按页码）与套卷两种模式，智能排期与进度预测
- **错题本**：自研自适应排期算法，三态评价，薄弱点看板与复习热力图
- **背书本**：新学/复习双窗口排期，艾宾浩斯与均匀间隔双模式

### AI 学习助手

- 用户自行配置大模型 API Key，系统仅做代理转发
- Function Calling 工具调用，AI 自主查询学习数据并给出基于真实数据的建议
- 联网搜索（Tavily），搜索结果附参考文献
- 长期记忆：自动提取用户学习习惯，后续对话自动调用
- 今日任务时长预估：AI 预估 + 系统按打卡比例计算 + 用户手动校准

### 自习室与系统

- 自习室创建/加入，公开广场按热度排序，成员隐私分层
- 邮箱验证码注册，JWT 鉴权，多设备同步，离线优先
- 两级管理员权限，操作审计留痕，邀请码系统

## 技术架构

### 前端

- 原生 HTML5/CSS3/JavaScript（ES6+），无框架依赖、无构建步骤
- PWA：Service Worker 离线缓存，可添加到桌面
- 响应式布局，手机/平板/PC 全适配，深色模式

- SQLite 在线热备，每日定时备份
- Docker Compose 一键本地部署，GitHub Actions CI

## 核心技术设计

### 多端数据同步

采用「本地优先 + 云端同步」的最终一致性方案：

1. 所有操作即时写入浏览器本地存储，不依赖网络
2. 登录后自动同步，服务端按 `updatedAt` 时间戳执行 LWW（Last-Write-Wins）合并
3. 墓碑机制记录删除操作，防止已删数据在多端同步时复活
4. ETag 增量同步：数据未变时返回 304，节省流量
5. 本地存储三层备份（localStorage + IndexedDB + Cache API），单层出问题可自动降级恢复

### 智能排期算法系统

三大学习模块各有针对性的排期算法，而非简单套用固定间隔：

**刷题本 — 动态追赶与可行性预测**

- **按期方案智能选择**：从「每周学习天数 × 每日学习量」的多个组合中，综合选择最易坚持的方案（优先每周 6 天而非每天都学，留缓冲）
- **EWMA 自适应速率**：用指数加权移动平均计算用户实际学习速率（半衰期 14 天，窗口 28 天），比简单平均更能反映近期状态
- **四级可行性评估**：ok / tight / stretch / impossible，提前预警是否能在截止日前完成
- **临考策略**：支持冲刺模式暂停新内容、战略放弃指定范围，把精力集中在高价值内容

**错题本 — 前紧后松自适应排期**

传统艾宾浩斯是固定间隔，不考虑错题动态增长、用户容量、考试截止日。本项目针对考研场景设计：

- **前紧后松预测**：根据历史错题收录速率预测未来新增量，提前均摊到每日，前期多排、后期平滑衰减，避免临考堆积
- **自动均衡摊派**：当日待复习超过用户容量时，自动将优先级最低的超额条目摊到未来；逾期过久的条目强制留当日，防止无限后推
- **主动提前复习**：当日到期量不足目标时，将近期将到期、薄弱优先的题目提前到当日，保持节奏稳定
- **舒适量与智能容量**：用户设定每日舒适量（默认错题 10 条/背书 6 条），系统在此基础上用 EWMA 实际速率动态调整硬上限——学得快的人不被固定值卡死，学得慢的人不被超额压垮
- **全局可行性预测**：综合剩余轮次、预测新增、剩余天数，提前判断能否在考试前完成

**背书本 — 新学/复习双窗口**

- **新学窗口与复习窗口分离**：新内容有截止学完日期，之后只复习不学新，保证考试前全部内容走完复习周期
- **均匀间隔模式**：将待复习内容平摊到每天，避免艾宾浩斯曲线天然的「某天爆量、某天无事」问题
- **舒适量双轨制**：每日目标 = 复习量 + 新学量，两者分别受舒适量约束，避免复习挤占新学或反之
- **保持期复习**：已掌握内容定期唤醒，间隔逐渐拉长（30→45→60 天），用最少复习量维持记忆

### AI 助手架构

**工具调用层（Function Calling）**

- 10+ 个数据查询工具：项目概览、每日进度、复习队列、薄弱点、自习室信息、任务时长预估等
- AI 自主判断何时调用、调用哪个、传什么参数，而非固定流程
- 工具返回结构化数据，AI 基于真实数据给出建议，避免空泛回答

**数据聚合层**

- 按需聚合：不同工具查询不同粒度数据，避免一次性传入全量数据浪费 token
- 敏感信息过滤：密码、邮箱、API Key 等绝不传入模型
- 上下文管理：对话历史按重要性截断，控制成本

**联网搜索**

- 集成 Tavily Search API，中文优化（language=zh-CN）
- AI 自主判断是否需要搜索（如目标院校信息、考试政策、科目经验）
- 搜索结果以「参考文献」形式附在回复末尾，用户可自行核实，AI 不替用户做最终判断
- 用户级搜索额度限制，防止滥用

**长期记忆系统**

- AI 在对话中自动识别值得记忆的用户信息（学习习惯、速度偏好、目标院校等），写回数据库
- 后续对话自动加载 Top N 条记忆，按强度排序
- 用户可查看、删除记忆；关闭记忆开关后不写入新记忆，但不删除旧记忆

**任务时长预估**

- 每日首次打开时，AI 根据今日任务清单 + 用户长期记忆，预估每项任务总耗时
- 打卡后系统按「已完成/总任务 × 预估总时长」比例计算已学时长，无需用户手动输入
- 用户可手动校准已学时长，校准值用于后续 AI 预估的个性化调整
- 任务总量变化时自动触发重新预估，已完成任务不触发

### 安全设计与边界处理

**认证与授权**

- 密码 bcrypt 加盐哈希存储，JWT 鉴权支持 `token_version` 强制下线
- 两级管理员权限：超级管理员唯一最高权限，普通管理员不可管理超级管理员
- 管理员危险操作需二次验证，操作全程审计留痕

**接口安全**

- CORS 白名单仅放行生产域名
- 接口按 IP 限流，防止暴力攻击
- CSP 内容安全策略防 XSS，用户输入统一 HTML 转义
- AI API Key 仅服务端代理使用，不回传前端

**数据安全**

- 服务以非特权用户运行，数据库文件权限收紧
- SQLite 在线热备，每日定时备份，防止数据丢失
- 用户数据导出/导入功能，支持自助迁移
- 自助注销账号，彻底删除用户数据

**边界与异常处理**

- 同步冲突：LWW + 墓碑机制保证多端最终一致性
- 离线操作：本地优先，联网后自动同步，冲突按时间戳解决
- 存储异常：三层备份自动降级，异常时弹窗提醒用户导出备份
- AI 服务异常：API 调用失败时友好提示，不影响核心学习功能
- 大文件上传：头像自动压缩，限制上传大小

## 快速开始

### 本地开发

```bash
# 后端
cd backend
npm install
node server.js

# 前端：直接用浏览器打开 frontend/index.html，或用任意静态服务器
```

### Docker 部署

```bash
cp .env.example .env  # 填入配置
docker-compose up -d
```

### 生产部署

1. 前端文件放 Web 服务器静态目录，预压缩 gzip/Brotli
2. 后端用进程管理器托管
3. 注意不要覆盖服务器上的环境配置文件（含密钥）
