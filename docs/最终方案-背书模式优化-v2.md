> - **①（固定容量高用户）**：`newLearnCap` 方向修正——填了就按用户值执行，不被 newCap 均摊压小。
> - **②（少量背书用户）**：smart 模式新增 `comfortAsHardCap` 硬封顶开关，开启后舒适量真的是天花板。
> - **③（少量背书用户）**：M2 中性提示加 `[挪走多余的]` 按钮，一键 spreadItems。

> - **⑤（临考冲刺用户）**：低频降频冲刺期只对 good 条目生效，fuzzy/forgot 保持 clamp 后 ≤3 天。
> - **⑥（临考冲刺用户）**：🔴 risk 文案按 reason 分叉（窗口已过+积压 vs 窗口内赶不及）。
> - **⑦（临考冲刺用户）**：clamp 说明文案用实际 gap 天数，不写死"3天"。
> - **⑧（进度落后用户）**：红绿灯加复习端积压判断（overdue>舒适量×3 → 至少 🟡）。
> - **⑨（进度落后用户）**：M2 文案明确承诺"超出部分自动摊到未来，不会堆成逾期"。
> - **⑩（考试日截止用户）**：新学窗口已关且仍有未学内容 → 返回 🟡 warn，不直接 ok。
> - **⑪（固定容量高用户）**：fixed 模式不弹调高舒适量建议，改成节奏肯定文案。
> - **⑫（固定容量低用户）**：M8 红灯条与 M6 策略条互斥，避免两条琥珀条并排。
> - **⑬（少量背书用户）**：M9 软鼓励加 stage 分组提示（老朋友/新内容）。
> - **⑭（背书错题混合用户）**：毕业确认弹窗按类型分支（"掌握"vs"攻克"）。
> - **⑮（背书错题混合用户）**：低频降频措辞背书化。
> - **⑯（考试日截止用户）**："准备二战"按钮改为先归档当前项目再开新周期，不改当前 deadline。
>
> **v2 backlog（明确不做，留后续版本）：**
> - 批量粘贴拆条录入
> - 背书↔错题条目级双向关联
> - 背书独立的"遗忘原因"标签
> - classic 模式录入错峰提示
>
> **v1 已确认满意、v2 不改的部分**：M1 fixed 解耦舒适量截断、M4 过期文案按类型区分、M5 归档、M7 录入错峰、M10 设置页隐藏错题指南按钮。
>
> **最高产品约束（同 v1，编码时不得违背）：**
> 1. 后移截止日不是首选；`hardDeadline===true` 全程不见后移；后移仅作最后兜底且带"如果不是硬约束"。
> 2. 所有新 UI 都在背书本页面内，不碰 Dashboard/今日总览。
> 3. 提示可关闭但只当天有效（写 `xxxShownDate/DismissedDate = todayStr()`），无永久静音。
> 4. 舒适量建议不死锁：触发靠"连续轻松/吃力"行为信号；"最近 7 天实际日均"只作为文案参考与建议值贴近度，不直接把舒适量设成 EWMA、不自动改。
> 5. 舒适量下限：smart 模式（avg）不低于 4（绝对底 3），固定模式（fixed）不卡下限——用户自己锁的日量。
> 6. 老用户兼容：新字段迁移层兜底，老数据不崩。
> 7. 不改 mistake / exercise 已优化代码（只调用 `scheduleNextReview`、`transitionReview` 等共享内核函数）。
> 8. 背书有自己的三态间隔重复内核（记得/模糊/忘记），方案必须尊重这个内核，不破坏。
> 9. 术语口径：背书统一用"掌握/条/背诵"，错题用"攻克/道/错题"；代码变量 `isMastered` 不变。

## 0. 一句话总览

背书（recite）复用了错题本的三态间隔重复内核，但外围调度层是"半套"。v2 在 v1 基础上修正了 16 条评审意见，核心变化：**newLearnCap 方向修正（用户设值不被均摊压小）、smart 模式加硬封顶开关、策略条触发条件放宽、低频降频冲刺期只对 good 生效、可行性红绿灯加复习端判断、risk 文案按 reason 分叉**。

## 3. 核心算法：背书每日目标（复习 + 新学双轨）

```js
// 取舒适复习量
function getReciteComfort(p) {
  let c = parseInt(p.spreadThreshold, 10);
  if (!isFinite(c) || c < 1) c = 6;
  c = Math.round(c);
  if (p.reciteMode === 'fixed') {
    return Math.max(1, c);                 // fixed：不卡下限，用户自定
  }
  return Math.max(4, c);                   // smart：下限 4（绝对底 3）
}

// 每日复习目标（due items 侧）
function getReciteReviewTarget(p, date) {
  const comfort = getReciteComfort(p);
  if (p.reciteMode === 'fixed' && p.dailyCapacity != null) {
    return Math.max(1, Math.round(p.dailyCapacity));  // fixed：锁死容量，不受舒适量截断
  }
  // smart 模式
  const cap = getDailyCapacity(p, date);           // 现有函数，不改
  const today = todayStr();
  if (date === today) {
    // [v2·②] 硬封顶开关开启时，舒适量是天花板
    if (p.comfortAsHardCap === true) {
      return Math.min(comfort, Math.max(comfort, cap));  // = comfort，超出自动spread
    }
    return Math.max(comfort, cap);
  }
  return Math.max(1, Math.min(50, cap));
}

// 每日新学目标（newCap 侧）
function getReciteNewLearnTarget(p) {
  if (p.pauseNewLearning) return 0;               // 暂停新学开关
  const newCap = getDeadlineLevelCap(p).newCap || 0;  // 现有函数，不改
  // [v2·①修正] 填了 newLearnCap 就按用户值执行，不被 newCap 压小
  if (p.newLearnCap != null && isFinite(p.newLearnCap)) {
    return Math.max(0, Math.round(p.newLearnCap));
  }
  return newCap;                                   // null = 自动均摊
}
```

**v2 关键修正说明：**
- **① newLearnCap 方向修正**：v1 写的是 `min(newCap, newLearnCap)`，用户设 30 但系统均摊只有 10 → 被压成 10。v2 改为：填了就按用户值执行，`return Math.max(0, p.newLearnCap)`。留空才走自动均摊 newCap。
- **② comfortAsHardCap 硬封顶**：smart 模式新增开关，默认 false（舒适量是地板）。用户开了之后，舒适量变成天花板，超出部分自动 spread 到未来。
- **⑤ 低频降频冲刺期修正**：见 M6 详细设计。

## 4. 逐模块详细设计（触发条件 / UI 位置 / 文案 / 按钮行为 / 边界）

> 所有 UI 都在背书本页面内（约束 2）。

### M1　舒适量 / 容量 / 新学上限设置

- **触发条件**：设置页对 recite 开放。新建 `reciteMode='smart', newLearnCap=null, comfortAsHardCap=false`。
- **UI 位置**：设置页"📈 每日节奏"区块（目标日下方）。包含：
  - 单选 `○ 智能节奏` / `○ 固定复习容量`
  - 智能模式显示：
    - `每天舒适复习 ___ 条`（默认 6，下限 4）
    - **[v2·②新增]** checkbox `☐ 把舒适量作为每日硬上限（超出自动往后排）`
  - 固定模式显示：`每天固定复习 ___ 条`（不卡下限）
  - 独立滑块：`每天新学上限 ___ 条（留空=自动按考试日均摊）`
- **校验**：
  - smart 模式：解析后 `<4` → 自动抬到 4，toast `智能模式下每日舒适复习量最低为 4 条，已按 4 保存`（绝对底 3）。
  - fixed 模式：**不校验下限**。允许填 5、3、1；仅把 ≤0/NaN 兜底为 1。
  - newLearnCap：填 0 允许（等于手动暂停新学），留空 = null（自动）。
- **区块灰字说明**：
  > "智能节奏：按考试日自动均摊复习量。勾选「硬上限」后每天最多只排舒适量那么多条，多余的自动往后排。固定复习容量：每天就做你设的这个量。新学上限：控制每天新背多少条，填了就按这个数来，留空则系统按考试日自动算。"
- **配置矛盾提示（修复固定容量高用户痛点）**：
  - 触发条件：`reciteMode==='fixed'` 且 `dailyCapacity > getReciteComfort(p)` 且 `configWarnDismissedDate !== today`。
  - 文案：`⚖️ 你设了每天固定复习 {cap} 条，当前舒适量参考是 {comfort} 条。固定模式下按 {cap} 条执行，不受舒适量限制。`
  - 按钮：`[知道了]` → `configWarnDismissedDate = today`（当天有效）。
- **边界**：fixed 锁 30、smart 舒适量才 6 → 不报错。

### M2　超量中性提示 + "挪走多余的"按钮

- **触发条件**：全部满足——
  1. `p.type==='recite'`，`!p.archived`；
  2. `p.reciteMode==='smart'` 且 `p.comfortAsHardCap !== true`；
  3. 当日复习目标 `getReciteReviewTarget(p, today) > getReciteComfort(p) × 1.3`；
  4. `p.comfortHintShownDate !== todayStr()`（每天最多 1 次）；
  5. M6 临考策略条不显示时才显示（互斥）。
- **UI 位置**：复习列表顶部，琥珀色中性小条（复用 `.neutral-banner` 样式）。
- **文案（v2·⑨修正，明确承诺）**：
  > "📚 今天系统计划复习 **{target}** 条，你的舒适量是 **{comfort}** 条。先按舒适量做就好，**超出的部分系统会自动摊到未来几天，不会堆成逾期**。"
  >
  > （source 来源拆解：多出的部分主要来自 {source}——积压追赶/考试日均摊/星期画像）
- **按钮（v2·③新增）**：
  - `[挪走多余的]` → 调用 `spreadItems(p, today, { keep: comfort })`，把今天 due 中超出 comfort 的条目摊到未来 2–3 天。挪完今日待办数字立刻变小。
  - `[✕]` → `p.comfortHintShownDate = todayStr()`（当天有效）。
- **边界**：
  - fixed 模式不触发（用户自己锁的量）；
  - `comfortAsHardCap===true` 时不触发（已经硬封顶了，不需要提示）；
  - hardDeadline 也显示但不提后移。

### M3　舒适量智能建议（调高 / 调低）

- **统计口径**：新增 `getReciteStreak(p)`，只看 items 里 reviews 记录的学习日完成量 vs comfort。
- **三条建议（互斥，每天最多弹 1 条）**：
  1. **调高建议（仅 smart 模式触发，v2·⑪修正）**：
     - 触发：`p.reciteMode==='smart'` + 连续 ≥7 学习日 `完成复习数 ≥ comfort × 1.3` + 距 deadline>14 天 + 当天未弹。
     - 文案：
       > "💡 你已连续 7 天轻松完成 {comfort} 条复习，最近 7 天实际日均约 **{avg7}** 条，状态不错。要不要把每日舒适复习量调到 **{suggestUp}** 条试试？（可随时调回）"
     - `avg7` = 最近 7 个学习日的平均完成复习数（仅作文案参考）；`suggestUp = Math.min(50, Math.max(comfort+2, Math.round(avg7)))`。
  2. **fixed 模式：不建议调高舒适量（v2·⑪新增）**：
     - fixed 模式下连续 7 天轻松完成 → 不弹调高建议，改为目标卡下方一行灰字（不弹条）：
       > "你最近日均 {avg7} 条且节奏稳定，继续保持就好。"
  3. **smart 模式调低建议**：连续 ≥21 学习日 `完成复习数 < comfort × 0.7` + backlog 稳定或下降 + 距 deadline>30 天 + `hardDeadline!==true` + 当天未弹。
     - 文案：
       > "💡 你最近的实际节奏约 {avg7} 条/天，低于舒适量 {comfort} 条。要不要把舒适量调到 **{suggestDown}**？状态好再往上加。"
     - `suggestDown = Math.max(4, Math.round(avg7))`（不低于下限 4）。
     - **`hardDeadline===true` 时整条不显示**。
- **按钮行为**：`[好，调到 N]` → `p.spreadThreshold=N`（smart 模式仍夹到下限 4）；`[不用]` → 当天关闭。
- **边界**：建议调高封顶 50；不自动改任何值。

### M4　过期处理（文案按类型区分 + hardDeadline 归档优先 + 二战按钮确认）

- **触发条件**：`p.deadline < todayStr()`、`!p.archived`、有未掌握条目。
- **UI 位置**：复用 `#deadlinePassedBanner`（app.js:6523），背书已显示，**只需修文案**。
- **文案修复（P2-01）**：
  - `app.js:6563` → recite: `这本背书本陪你走过了备考的日子`
  - `app.js:6968` → recite: `待复习条目会越攒越多`
  - `app.js:6990-6992` honestHint → 合并为一条，按类型区分用词。
- **横幅按钮**：
  - **普通过期（hardDeadline=false 或未标记）**：
    - 刚过期（首次打开后≤3天）：`📌 目标日刚过去，还有 **{N}** 条未掌握` + `[重设目标日]` `[一键重排旧题]` `[继续不赶进度]` `[归档这本]`

  ```js
  function getReciteFeasibility(p) {
    const cycleDays = getReviewCycleDays(p);
    const d2d = diffDays(todayStr(), p.deadline);
    const comfort = getReciteComfort(p);
    const overdue = getOverdueItems(p).length;
    const unlearned = getUnlearnedCount(p);

    if (d2d <= 0) return { level: 'ok', reason: 'expired' };

    // [v2·⑧] 复习端积压判断：overdue > 舒适量×3 → 至少 warn
    if (overdue > comfort * 3) {
      return { level: 'warn', reason: 'review_backlog_heavy', overdue };
    }

    const newLearnEnd = addDays(p.deadline, -cycleDays);
    const daysLeftNew = diffDays(todayStr(), newLearnEnd);

    // [v2·⑩] 新学窗口已关且仍有未学内容 → warn，不直接 ok
    if (daysLeftNew <= 0) {
      if (unlearned > 0) {
        return { level: 'warn', reason: 'new_window_closed_still_unlearned', unlearned };
      }
      // 新学窗口已关且全部学完 → ok
      if (overdue > 0) {
        return { level: 'warn', reason: 'newLearnEnd_passed_with_backlog', overdue };
      }
      return { level: 'ok', reason: 'newLearnEnd_passed' };
    }

    // 新学窗口内：按当前节奏能不能学完？
    const ewmRate = getEwmRate(p, today);
    const neededPerDay = Math.ceil(unlearned / daysLeftNew);
    if (ewmRate > 0 && neededPerDay > ewmRate * 1.5) {
      return { level: 'risk', reason: 'new_learning_too_slow', neededPerDay, ewmRate };
    }
    if (ewmRate > 0 && neededPerDay > ewmRate * 1.2) {
      return { level: 'warn', reason: 'new_learning_tight', neededPerDay, ewmRate };
    }

    // [v2·⑧] 正常状态下 overdue>0 也给一行小字提示（不升级为 warn）
    return { level: 'ok', reason: 'on_track', overdueHint: overdue };
  }
  ```
- **红绿灯显示（v2·⑥文案按 reason 分叉）**：

## 7. Scope 边界（明确不做）

### v2 明确不做（backlog）
1. **批量粘贴拆条录入**——v1 只修单条录入错峰，批量导入留 v3。
2. **背书↔错题条目级双向关联**——背书错题混合用户的需求，留 v3 评估。
3. **背书独立的"遗忘原因"标签**——errTags 字段保留但 UI 不暴露，留 v3。
4. **classic 模式录入错峰提示**——v2 只修 balanced 模式录入错峰，classic 模式提示留 v3。

### 通用不做（同 v1）
5. 不做 item 级自定义间隔 UI。
6. 不做跨项目时间预算/混合任务视图。
7. 不自动推断章节高频/考纲权重。
8. 不改任何 mistake / exercise 专属函数逻辑。
9. 不在 Dashboard/今日总览加新 UI。
10. 不做永久静音；关闭只当天有效。
11. 后移截止日不作首选；hardDeadline 全程不见后移。
12. 舒适量建议不自动改；fixed 不劝降。
13. 不破坏三态间隔重复内核。

## 9. 验收清单（交编码代理后逐条核对）

- V1（M1·①）newLearnCap 填 30、newCap 自动均摊只有 10 → 每日新学目标 = 30（不被压小）。留空 → 走 newCap 自动均摊。
- V2（M1·②）smart 模式勾选 comfortAsHardCap → 每日复习目标 = min(舒适量, cap)，超出自动 spread。
- V3（M1）smart 模式输入 3 条舒适量 → 自动抬到 4 + toast；fixed 模式输入 5 → 直接存 5、复习目标=5（不被舒适量截断）。
- V4（M2·③）smart 模式当日复习目标 > 舒适量×1.3 → 琥珀中性条显示，带 [挪走多余的] 按钮，点击后今日待办数字变小。
- V5（M2·⑨）中性条文案含"超出的部分系统会自动摊到未来几天，不会堆成逾期"。
- V6（M3·⑪）fixed 模式连续 7 天轻松 → 不弹调高建议，只一行灰字"节奏稳定"。
- V7（M3）smart 连续 7 天完成 ≥ 舒适量×1.3 → 建议"调到 {suggestUp}"，文案含最近 7 天日均。
- V8（M4·⑯）hardDeadline=true 过期 → "准备二战"按钮点击后先归档当前项目，再跳新建项目流程，不改当前 deadline。
- V9（M4）过期横幅 recite 显示"这本背书本"不是"错题本"；身后排队文案说"条"。
- V10（M6·④）overdue > 舒适量×3 → 策略条显示（不管 d2d 多少）。
- V11（M6·④）新学窗口已关且 unlearned>0 → 策略条显示。
- V12（M6·④）设置页常驻"暂停新学"toggle，任何时候可开/关。
- V13（M6·⑤）冲刺期开启 lowFreqExtended → fuzzy/forgot 条目间隔保持 ≤3 天，只有 good 条目被 ×1.5 拉长。
- V14（M6·⑦）冲刺期点"忘记" → 反馈区小灰字"已安排{gap}天后重现"，gap 是实际天数。
- V15（M6·⑮）低频降频开启时灰字说明："已掌握较久、状态稳定的条目，复习间隔拉长，腾出时间给模糊项。"
- V16（M7）balanced 模式录入 10 条 → 首次复习日分散到未来 1–7 天。
- V17（M8·⑧）overdue > 舒适量×3 → feasibility 返回至少 🟡 warn，文案"复习端压力较大"。
- V18（M8·⑩）新学窗口已关且 unlearned>0 → 返回 🟡 warn，不直接 ok。
- V19（M8·⑥）risk reason=newLearnEnd_passed_with_backlog → 建议不含"调高新学上限"。
- V20（M8·⑫）M6 策略条显示时，M8 红灯条不单独弹，只保留灰字结论。
- V21（M9·⑬）逾期条目旁显示 stage 分组提示（老朋友/新内容）。
- V22（M10·⑭）毕业确认弹窗：recite 问"确认掌握了吗"，mistake 问"确认攻克了吗"。
- V23（约束）所有 ✕ 只写当天日期；hardDeadline 全程无后移；mistake/exercise 专属函数零改动；三态内核 transitionReview/applyReview 逻辑零改动。
