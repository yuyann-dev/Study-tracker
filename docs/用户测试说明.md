# 用户测试与迭代说明

## 测试方法论

本项目采用「多角色用户模拟 + 专家评审 + 体验验证」三层测试体系，在开发过程中持续迭代。

### 为什么这样做

考研学习工具的用户差异极大：有人每天学 12 小时，有人只能挤 3 小时；有人临考才开始刷题，有人从一年前就稳步推进；有人只用错题本，有人三科混合使用。单一视角的测试无法覆盖这些场景，因此需要模拟不同画像的真实用户，在使用中发现问题。

### 测试流程

```
用户模拟（按画像真实使用）
    ↓ 发现问题
用户代理评审（汇总问题、给出改进建议）
    ↓ 确定方案
开发迭代
    ↓
体验评审（验证修复效果、检查回归）
    ↓
下一轮模拟
```

## 覆盖的用户画像

### 按学习强度

| 画像 | 说明 |
|---|---|
| 低强度用户 | 每天可学 3-4 小时，在职或跨考 |
| 固定容量用户 | 每天学习时间稳定，高/低两档 |
| 高强度用户 | 每天 8+ 小时，全职备考 |
| 冲刺期用户 | 考前 30-60 天，节奏紧张 |

### 按备考阶段

| 画像 | 说明 |
|---|---|
| 正常推进 | 距考试 3 个月以上，按部就班 |
| 截止日偏紧 | 目标日设置偏激进，容易积压 |
| 考试日截止 | 截止日直接设为考试当天，无缓冲 |
| 已过期用户 | 目标日已过，系统进入兜底模式 |
| 临考积压 | 考前错题/背诵大量堆积 |
| 进度落后 | 实际进度明显落后于计划 |

### 按使用模块

| 画像 | 说明 |
|---|---|
| 错题本用户 | 主要用错题本功能 |
| 刷题本用户 | 主要用刷题本功能 |
| 背书本用户 | 主要用背书功能 |
| 混合场景用户 | 三科混合使用，关注跨模块联动 |

## 文档说明

- `用户模拟-*.md`：按用户画像撰写的真实使用记录，包含使用过程、遇到的问题、主观感受
- `用户代理评审-*.md`：汇总该类用户的核心问题，按优先级给出改进建议
- `用户评审-*.md`：针对特定方案的用户视角评审
- `体验评审-*.md`：迭代后的体验验证报告，确认问题修复、检查回归

## 迭代原则

1. **用户问题优先**：所有改动均来自真实使用场景中发现的问题，不做无依据的"优化"
2. **小步快跑**：每轮只解决最痛的 2-3 个问题，避免大改引入回归
3. **可验证**：每个改动都有对应的用户体验验证记录
4. **边界情况必测**：过期、积压、混合使用等边界场景是测试重点

## 测试工具说明

用户模拟部分借助 AI 辅助生成不同画像的使用视角，用于快速覆盖多样场景；安全测试部分由 AI 模拟攻击者角色，辅助发现边界情况和潜在漏洞。
