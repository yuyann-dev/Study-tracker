# 用户测试与迭代说明

## 测试方法论

本项目采用「多角色用户模拟 + 专家评审 + 体验验证」三层测试体系，在开发过程中持续迭代。

### 为什么这样做

考研学习工具的用户差异极大：有人每天学 12 小时，有人只能挤 3 小时；有人临考才开始刷题，有人从一年前就稳步推进；有人只用错题本，有人三科混合使用。单一视角的测试无法覆盖这些场景，因此需要模拟不同画像的真实用户，在使用中发现问题。

### 测试流程

```
用户模拟（按画像真实使用）
    ↓ 发现问题
用户代理评审（汇总问题、给出改进建议）
    ↓ 确定方案
开发迭代
    ↓
体验评审（验证修复效果、检查回归）
    ↓
下一轮模拟
```

## 覆盖的用户画像

### 按学习强度

| 画像 | 说明 |
|---|---|
| 低强度用户 | 每天可学 3-4 小时，在职或跨考 |
| 固定容量用户 | 每天学习时间稳定，高/低两档 |
| 高强度用户 | 每天 8+ 小时，全职备考 |
| 冲刺期用户 | 考前 30-60 天，节奏紧张 |

### 按备考阶段

| 画像 | 说明 |
|---|---|
| 正常推进 | 距考试 3 个月以上，按部就班 |
| 截止日偏紧 | 目标日设置偏激进，容易积压 |
| 考试日截止 | 截止日直接设为考试当天，无缓冲 |
| 已过期用户 | 目标日已过，系统进入兜底模式 |
| 临考积压 | 考前错题/背诵大量堆积 |
| 进度落后 | 实际进度明显落后于计划 |

### 按使用模块

| 画像 | 说明 |
|---|---|
| 错题本用户 | 主要用错题本功能 |
| 刷题本用户 | 主要用刷题本功能 |
| 背书本用户 | 主要用背书功能 |
| 混合场景用户 | 三科混合使用，关注跨模块联动 |

## 文档说明

- `用户模拟-*.md`：按用户画像撰写的真实使用记录，包含使用过程、遇到的问题、主观感受
- `用户代理评审-*.md`：汇总该类用户的核心问题，按优先级给出改进建议
- `用户评审-*.md`：针对特定方案的用户视角评审
- `体验评审-*.md`：迭代后的体验验证报告，确认问题修复、检查回归

## 迭代原则

1. **用户问题优先**：所有改动均来自真实使用场景中发现的问题，不做无依据的"优化"
2. **小步快跑**：每轮只解决最痛的 2-3 个问题，避免大改引入回归
3. **可验证**：每个改动都有对应的用户体验验证记录
4. **边界情况必测**：过期、积压、混合使用等边界场景是测试重点

## 测试工具与方法说明

### 用户模拟测试

本项目在开发过程中使用大语言模型工具辅助进行多角色用户模拟测试，以快速覆盖考研学生群体中多样的使用场景和画像差异。具体做法：

1. **模拟不同类型用户**：针对错题本、刷题本、背书本三个核心模块，分别模拟了低强度用户（每天3-4小时）、固定容量用户（高/低两档）、高强度用户（每天8+小时）、冲刺期用户（考前30-60天）、截止日偏紧用户、考试日截止用户、已过期用户、临考积压用户、进度落后用户等多种画像，每个画像独立撰写真实使用记录。

2. **模拟混合使用场景**：除单模块用户外，还模拟了三科混合使用（数学+政治+英语错题并行）、刷题错题联动、背书错题混合等跨模块场景，重点关注模块间数据一致性和联动体验。

3. **生成测试报告**：每类用户模拟后均生成独立的使用记录文档（`用户模拟-*.md`），包含使用过程、遇到的问题、主观感受和改进建议；再由用户代理评审汇总（`用户代理评审-*.md`），按优先级给出改进方案；开发迭代后进行体验验证（`体验评审-*.md`），确认问题修复并检查回归。

4. **多轮迭代**：上述"模拟→发现问题→评审→开发→验证"流程循环进行，错题本、刷题本、背书本各完成至少两轮完整迭代，确保不同画像用户的核心痛点都被覆盖和解决。

### 安全与边界测试

同样使用大语言模型工具模拟攻击者角色和异常输入场景，对系统的安全边界进行压力测试：

1. **API Key 安全**：模拟 Key 泄露、Key 无效、额度不足、网络超时、模型限流等场景，验证加密存储（AES-256-GCM）、掩码回显、零日志、SSRF 防护等机制是否生效。

2. **数据注入防护**：模拟 Prompt 注入（在学习数据中嵌入"忽略上文""执行指令"等恶意文本）、XSS 注入（在项目名、条目内容中插入脚本标签）、越权访问（尝试读取其他用户数据）等攻击向量，验证数据包裹、esc 渲染、白名单校验等防护是否有效。

3. **边界情况处理**：模拟空输入、超长输入、非法参数、并发操作、离线状态、数据损坏等异常场景，验证系统的降级策略和错误处理是否健壮。

4. **成本保护**：模拟高频调用、超长对话、token 超限等场景，验证单日预算上限、失败不计费、消耗估算等机制是否正常工作。

安全测试结果汇总在 `体验评审-混合场景与安全.md` 中，包含 API Key 保护、数据安全、10 项边界处理、成本保护四个维度的逐项检查清单和评分。

### 说明

以上用户模拟和安全测试均借助大语言模型工具辅助生成多视角测试用例和报告，用于快速覆盖人工测试难以穷尽的多样场景和边界情况。所有发现的问题均经过人工确认后才进入开发迭代，最终修复效果由人工验证确认。
