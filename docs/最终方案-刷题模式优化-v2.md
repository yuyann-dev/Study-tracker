> 6. 老用户兼容：新字段迁移层兜底，老数据不崩。

## 0. 一句话总览

exercise 是"剩余量 ÷ 剩余学习日"的纯进度推进器（`p.items` 恒空，进度全在 `p.records[]`）。本方案**不造 due 队列**，围绕四件事：把每日目标收敛到用户能接受的节奏、补过期/临考/收尾闭环、刷题错题一键搬运、给高强度用户刹车与领先播报。

核心：新增 `dailyComfort` + `exerciseMode`（avg/fixed），实际每日目标 = fixed 取舒适量、avg 取 `min(舒适量, 均摊量)`；v2 进一步把舒适量下限分模式放开，并在 M2b/M6/M8/M9/M10 补齐刹车、提醒、透明与入口。

## 3. 核心算法：exercise 每日目标（v2 修订下限）

```js
// [v2·A] 取舒适量，下限按模式区分
function getExerciseComfort(p) {
  let c = (typeof p.dailyComfort === 'number' && isFinite(p.dailyComfort)) ? p.dailyComfort : 6;
  c = Math.round(c);
  if (p.exerciseMode === 'fixed') {
    return Math.max(1, c);                 // fixed：完全豁免下限，允许 5、3、1…用户自定
  }
  return Math.max(4, c);                   // avg：下限 4（绝对底 3，见 M1 校验）
}

// [v2] 实际每日目标（per 公式同 v1，不改——评审满意）
function getExerciseDailyTarget(p, m) {
  const comfort = getExerciseComfort(p);
  const remaining = Math.max(0, m.remaining || 0);
  if (remaining <= 0) return { per: 0, mode: p.exerciseMode, comfort, avgPer: 0, capped:false, remaining:0 };

  const raw = getDailyTarget(p, m);                 // 现有函数，不改
  const avgPer = (raw.per != null && raw.per > 0) ? raw.per
              : (isFinite(m.needPerDay) && m.needPerDay > 0) ? m.needPerDay : comfort;

  let per;
  if (p.exerciseMode === 'fixed') per = comfort;    // 固定容量：锁死舒适量
  else per = Math.min(comfort, avgPer);             // 均摊：min(舒适量, 均摊量) 封顶不追高
  per = Math.min(per, remaining);
  return { per: round1(per), mode: p.exerciseMode, comfort,
           avgPer: round1(avgPer),
           capped: (p.exerciseMode !== 'fixed') && (avgPer > comfort + 1e-9),
           remaining };
}
```

**v2 下限规则（A，来自少量刷题 + 固定容量低 用户）：**
- avg 模式：舒适量 = `max(4, 用户值)`；输入 <4 时校验抬到 4。
- fixed 模式：舒适量 = `max(1, 用户值)`，**不卡 6/不卡 4**——fixed 的全部意义就是用户自己定日量（用户要锁 5 就 5，要锁 3 就 3）。

## 4. 逐模块详细设计（触发条件 / UI 位置 / 文案 / 按钮行为 / 边界）

> 所有 UI 都在刷题本页面内（约束2）。"页"=套卷模式的"套"。

### M1　舒适量 / 容量设置

- **触发条件**：设置页对 exercise 开放（M10）。新建 `dailyComfort=6, exerciseMode='avg'`。
- **UI 位置**：设置页"📈 每日节奏"区块（目标日下方）。输入 `每天舒适做 ___ 页` + 单选 `○ 均摊模式` / `○ 固定容量模式`。
- **校验（v2·A 修订，来自少量刷题 + 固定容量低 用户）**：
  - avg 模式：解析后 `<4` → 自动抬到 4，toast `均摊模式下每日舒适量最低为 4 页，已按 4 保存`（绝对底 3：极端脏值不低于 3）。
  - fixed 模式：**不校验下限**。允许填 5、3、1；仅把 ≤0/NaN 兜底为 1。
  - 切模式时不强制改 comfort 值（用户从 avg 切 fixed，那个 4 就当固定日量用）。
- **具体文案（区块灰字）**：
  > "均摊模式：按剩余页数÷天数给建议，但每天不超过你的舒适量（最低 4 页）。固定容量模式：每天就做你设的这个量，做完即打勾，数量不设下限。"
- **按钮行为**：保存 `p.dailyComfort`/`p.exerciseMode` → render() 立即按 §3 重算。
- **边界**：fixed 锁 30、均摊才 5 → 不报错，目标卡下方给小字参考（M8）。

### M2　超量 / 落后中性提示（"系统计划 X，你的舒适量是 Y"）

> v1 评审满意，**不改**。保留：avg 模式且 `capped===true`（avgPer>comfort）、未过期、当天未弹、M6 不显示时，琥珀色中性条 `按目标日摊到每天约需 {avgPer} 页；你的舒适量 {comfort} 页，先按 {comfort} 推进`，✕ 只当天有效。hardDeadline 也显示但不提后移。

### M2b　刷爆刹车提醒（v2 新增·F，来自固定容量高 用户）

- **触发条件**：全部满足——
  1. `p.type==='exercise'`，`!p.archived`；
  2. `p.exerciseMode==='fixed'`；
  3. 当天 `m.todayDone > comfort × 1.5`；
  4. `p.brakeShownDate !== todayStr()`（每天最多 1 次）。
- **UI 位置**：目标卡下方，琥珀色中性小条（同 M2 样式）。
- **具体文案**：
  > "🛑 今天已做 {done} 页，远超你的日常节奏 {comfort} 页。注意消化，可以翻一翻前几天做过的章节，别只赶页数。"
- **按钮行为**：`✕` → `p.brakeShownDate = todayStr(); saveStore(); render();`（当天有效）。
- **边界**：只 fixed 模式触发（avg 模式超额=被封顶后仍冲，不归此处）；avg 模式的超额反馈走 M9/J。

### M3　舒适量智能建议（v2 重写·D，来自固定容量高 + 进度落后 + 大量刷题 用户）

- **统计口径**：新增 `getExerciseStreak(p, m)`，只看 records 里学习日完成量 vs comfort/avgPer，**不读 EWMA 作为触发**。
- **三条建议（互斥，每天最多弹 1 条）**：
  1. **调高建议（avg/fixed 通用）**：连续 ≥7 学习日 `done ≥ comfort×1.3` + 距 deadline>14 天 + 当天未弹。
     - 文案（v2 增强，来自大量刷题 用户）：
       > "💡 你已连续 7 天轻松完成 {comfort} 页，最近 7 天实际日均约 **{avg7}** 页，状态不错。要不要把每日舒适量调到 **{suggestUp}** 页试试？（可随时调回）"
     - `avg7` = 最近 7 个学习日的平均完成量（**仅作文案参考**）；`suggestUp = Math.min(30, Math.max(comfort+2, Math.round(avg7)))`——建议值更贴近实际，但仍**只建议不自动改**。
  2. **fixed 模式：不主动建议调低（v2 新增，来自固定容量高 用户）**。用户自己锁的硬日量，系统不劝降。删掉 v1 里 fixed 的调低建议。
  3. **avg 模式调低指引（v2 新增，来自进度落后 用户）**：avg 模式下连续 ≥5 学习日 `done < avgPer×0.8` + `m.daysLeft>0` + `p.hardDeadline!==true` + 当天未弹。
     - 文案：
       > "💡 你最近的实际节奏约 {avg7} 页/天，按这个速度预计 {m.etaDate} 完成。如果接受这个节奏，可以到设置里把目标日调成那天——系统不会替你改。"
     - 按钮：`[去设置调目标日]` → `openSettings()`（定位 deadline 框）；`[不用]` → 当天关闭。
     - **`hardDeadline===true` 时整条不显示**（deadline 不能动，见约束1）。
- **按钮行为**：`[好，调到 N]` → `p.dailyComfort=N`（avg 模式仍夹到下限 4）；`[不用]`/`[去设置]` 分支如上。
- **边界**：avg 调低建议**不直接改 deadline**，只指入口；建议调高封顶 30；不自动改任何值。

### M4　过期处理（放开过期横幅 + 状态卡不再画饼；v2·G 修订状态卡文案）

- **触发条件**：`p.deadline < todayStr()`、`!p.archived`、`m.remaining>0`。
- **UI 位置**：复用 `#deadlinePassedBanner`（app.js:5827），放开对 exercise 的隐藏（5830 不再对 exercise 早退；liveCount 对 exercise 取 `m.remaining`）。
- **横幅按钮（v1 满意，不改）**：普通过期 `[重设目标日][归档这本]`；`✕`/`以后再说` 只当天有效。
- **状态卡过期文案（v2·G 修订，来自考试日截止 用户）**：`getStatusMessage` 分支5（4547）对 exercise 过期时：
  - **`hardDeadline===true`**：
    > "考试已经结束了。之前刷的都还在，可以把这本归档收进收纳箱。"
    （**删掉** v1 的"可以重设目标日接着推"——死线用户考完不需要重设引导。）
  - **`hardDeadline!==true`**：保留 v1 文案
    > "已经过了原定目标日 {deadline}，还剩 {remaining} {u}。之前刷的都还在——可以重设目标日接着推，或者把这本归档收起来。"
  - 两种都**不渲染空 plan 块**（不画饼），真按钮由上方过期横幅提供。
- **hardDeadline 横幅**：沿用 v3 模式 `📚 考试已经结束了。这本刷题本陪你走过了备考的日子。`，主按钮 `[归档这本]`。
- **边界**：exercise 过期不调用 `rebalanceExpiredItems`（无 item，不碰 mistake 代码）。

### M5　归档功能（v1 满意，不改）

exercise 可归档：已完成条（`remaining===0` 时 `🎉 整本刷完了 [归档这本]`）+ 过期横幅 `[归档这本]`；收纳箱与"取消归档"对 exercise 已天然支持（renderProjectList 7664-7678 / data-unarchive 11868）。归档保留 records，不碰关联错题本。

### M6　临考策略条（v2 增强：砍题面板 + 错题逾期提醒 + 暂停新页空状态）

- **触发条件**：`!archived`、`remaining>0`、`0 < daysLeft <= 30`、落后（`m.behind >= comfort` 或 `feasibility==='impossible'`）、`p.sprintBarDismissedDate !== today`。独立新组件 `renderExerciseSprintBar`（不复用 mistake 的 tightStrategyBar）。
- **文案**：`⏳ 距目标日只剩 {daysLeft} 天，还剩 {remaining} {u}（落后约 {behind} {u}）。时间紧，做减法比硬赶新页更有效：`
- **三个按钮**：
  1. **[暂停新页，优先复习]** → toggle `p.sprintPauseNewPages=true`。
  2. **[砍题保分：标记低频章节放弃]** → 打开 `openAbandonPanel(p)`。
  3. **[把今天的错题送进错题本]** → 触发 M7 快录。
- **砍题保分面板（v2·C 增强，来自临考冲刺 + 考试日截止 用户）**：每行章节/范围显示——
  - **进度列**：`已做 X / 共 Y 页 · 剩 Z 页`（`X=该章节已合并区间页数`，`Y=该章节总页`，`Z=Y−X`）。
  - **错题数列**：聚合 linked mistake 本（`refProjectId===p.id`）里落在该章节 page 区间的 item 数 `n`：
    - `n >= 5` → 标绿 `建议保留`（错得多=该章高频/薄弱，值得刷）；
    - `n <= 1` → 标黄 `可考虑放弃`。
  - 数据来源：**只读 linked mistake 项目的 items + pageStart/pageEnd 聚合**，不接考纲、不自动推断高频。
  - 每行一个 `□ 战略放弃`，勾选写 `p.abandonedRanges/abandonedSets`，`getMetrics.total` 减去并实时回显："放弃 {n} 页后，每天从 {oldPer} 降到 {newPer}。"
- **暂停新页后的目标卡文案**：
  - 有 linked mistake → "今日停新页，去清关联错题本里的欠账" + `[打开关联错题本]`。
  - **空状态（v2·I 新增，来自临考冲刺 用户）**：无 linked mistake 时 → "停新页了。可以回顾之前打卡时标记过的错题记录，或者去创建一个关联错题本。" + `[去创建关联错题本]`（接既有 `openLinkedMistakes` 流程）。
- **日常错题逾期软提醒（v2·H 新增，来自刷题错题混合 用户）**：刷题本页面内（不碰 Dashboard），当存在 linked mistake 且 `getOverdueItems(linkedM).length > 0` 时，目标卡上方一行灰字：
  > "关联错题本已有 **N** 道逾期未复习，今天可以少刷 2 页新题，先去清一下。"
  （只读 linked mistake 的 overdue 数，不做全局时间建模。）
- **边界**：策略条与整段不出现"后移/延期"按钮；hardDeadline 照常显示；✕ 只当天有效；砍题可撤销。

### M7　错题联动（v2 增强：打卡快录 + 进度明细补记 + 每天限1次）

- **打卡快录（v1 保留，加频控）**：打卡成功（`btnCheckin` 12212 / `btnSetCheckin` 12143）后，若已关联 page/set mistake 本 **且 `p.wrongQuickRecordShownDate !== todayStr()`**，就地展开轻量弹层：
  > "这 {startPage}–{endPage} 页里有做错的题吗？如 45-12, 45-18（题号先占位）"
  `[记进关联错题本]` `[这次没有]`。任一操作（或关闭）后写 `p.wrongQuickRecordShownDate = todayStr()`——**[v2·B，来自大量刷题 用户]每天最多弹 1 次**。
- **写 linked mistake（不改 mistake 代码）**：按既有 item 形状（app.js:12344-12366）push，调既有 `scheduleNextReview(linkedM, item, date, 0)` 排期；同时把 marks 写回本次 record `r.wrongMarks`。
- **事后补记入口（v2·B 新增，来自临考冲刺 + 刷题错题混合 用户）**：进度明细 `openProgressBoard`（app.js:7683）里**每条 record 行增加"✏️ 补记错题"小按钮**，点开即可编辑该条 `r.wrongMarks`（新增/删除占位标记），保存后同步新增/删除对应的 linked mistake 占位条目（或仅在 exercise 本上维护 marks 集合，由一个"批量送入"按钮统一入库——二选一，推荐前者：编辑 marks 即增删占位条目）。**错题标记不再只在打卡后那几秒可录。**
- **无关联错题本**：快录按钮变成 `[去创建关联错题本]`，接既有 `openLinkedMistakes`。
- **边界**：mark 解析容错；题号留空则只记到页；不自动推断错因。

### M8　进度透明化（v2·E 增强，来自进度落后 + 大量刷题 用户）

- **触发**：点进 exercise 本，`m.total>0`。位置：目标卡下方一行灰字。
- **文案**：
  > "已做 **{currentPage}** / 共 **{total}** {u}"
  - **落后**（`m.behind > 0`）：`· 落后约 **{behind}** {u}（≈落后 **{behindDays}** 天）`，其中 `behindDays = Math.round(behind / avgPer)`。
  - **领先**（v2·E，`m.behind < 0`）：`· 领先约 **{-behind}** {u}（≈领先 **{-behindDays}** 天），按当前节奏预计 {etaDate} 完成`。
  - `m.etaDate` 存在时附 `按当前节奏，预计 {etaDate} 完成`；confidence 非 high 加灰字"估算会随记录修正"。
  - fixed 模式额外：`（固定每天 {comfort} {u}；照此节奏比目标日{早/晚}{diff} 天）`。
- **边界**：behind/eta 复用 getMetrics 既有字段；不放在 Dashboard。

### M9　软鼓励（v1 满意，不改）

做了但没达标（`done>0 && ratio<1`）时给低压力文案池（"已经做了 X，在往前走～没填满也没关系"）。done=0 走 idle；做满/超额走 done/over。

### M10　设置页优化（v2·K 增加战略放弃入口）

- 对 exercise 显示"每日节奏"区块（M1 输入 + avg/fixed 单选）；deadline 引导灰字（"日期越近每天页数越多；是考试日就勾选硬约束，系统不建议后移而帮你砍题保分"）；确保 `#sHardDeadline` 对 exercise 可见。
- **[v2·K，来自进度落后 用户]** "每日节奏"区块下新增 `✂️ 战略放弃部分页/套` 入口按钮——**任何时候都能打开 `openAbandonPanel(p)`，不锁死在临考 ≤30 天内**（用户日常也能砍范围）。
- exercise 仍不显示间隔表/复习模式单选/mistake 容量（避免误激活僵尸字段）。
- submitSettings：exercise 写 `p.dailyComfort`/`p.exerciseMode`（含 M1 的 avg<4 抬到 4 校验；fixed 不卡下限），不碰 mistake 的 spread/capacity 逻辑。

### M9b　领先播报（v2·J 新增，来自大量刷题 用户）

- **触发条件**：`renderDailyGoal` exercise 分支中 `ratio >= 2`（今天做了目标 2 倍以上）且 `m.behind < 0`（整体领先）且 `p.overLeadShownDate !== today`。
- **UI/文案**：目标卡 over 文案区追加一行琥珀色软播报：
  > "🎉 今天又超额啦！按这节奏你能提前约 **{leadWeeks}** 周刷完——要不要现在就把后面的复习规划上？"（`leadWeeks = Math.round((-behindDays)/7)`）
- **按钮**：`[去规划复习/暂停新页]` → 打开 M6 的"暂停新页"开关（`p.sprintPauseNewPages=true` 或打开策略条）。`✕` 当天有效。
- **边界**：只在领先（behind<0）时播；落后时超额不算"领先"，不播。

## 7. Scope 边界（明确不做）

1. 不做 item 级间隔复习/due队列/二刷提醒（v2 仍只做 record.wrongMarks）。
2. 不做跨项目时间预算/新题+错题混合任务视图（H 只读逾期数，不建模时间）。
3. 不自动推断章节高频/考纲权重（C 的"建议保留/放弃"只来自 linked mistake 错题数）。
4. 不激活 classic/balanced 间隔、不读 intervals 表。
5. 不改任何 mistake 专属函数逻辑。
6. 不在 Dashboard/今日总览加新 UI。
7. 不做永久静音；关闭只当天有效。
8. 后移截止日不作首选；hardDeadline 全程不见后移（D 的 avg 调低也只"指入口"，不代改 deadline）。
9. 舒适量建议不自动改；fixed 不劝降；建议值参考最近7天日均但不直接设成 EWMA。
