# 背书模式（recite）排期逻辑盘查

> 盘查范围：`frontend/js/app.js`（约 14900 行）、`frontend/index.html`、`frontend/css/style.css`
> 盘查方式：只读，不修改任何代码。所有行号以当前仓库 HEAD 为准。
> 术语对齐：代码里背书类型标识是 **`recite`**（不是 `memorize`）；用户可见文案统一叫"背书/掌握"。
> 参照系：错题本（mistake）与刷题本（exercise）已经过大范围优化，本文只做"背书盘查 + 与二者对比"，不改错题/刷题已优化代码。

## 0. 一句话结论

背书（recite）**复用了错题本的"三态间隔重复内核"**（`transitionReview` / `applyReview` / `getDueItems` / `renderReview` 完全共用），但**在外围调度层是"半套"**：
- ✅ 共享：三态间隔模型、保持期复习、均匀错峰（balanced）、自动均衡、配置矛盾提示、过期横幅、身后排队。
- ❌ **不共享（错题专属，背书走 `return 0 / {level:'ok'}` 直接短路）**：可行性警告 `getMistakeFeasibility`、主动提前 `pullForwardIfNeeded`、安全网 `ensureAtLeastOneReview`、今日收尾 `settleToday`、"前紧后松" `getMistakeDayPlan`、策略条上的「战略性后置 / 暂停新学 / 低频降频」按钮。
- ➕ **背书独有**：新学窗口（newLearnEnd = deadline − 完整复习周期）、冲刺期重排 `rebalanceForSprint`、`scheduleNextReview` 里的冲刺 clamp、按书页顺序聚簇排序。

整体没有阻断性 P0，但存在 **2 个 P1 设计缺口** 和一批 P2 文案/死代码/双实现漂移问题（见第 8 节）。

背书核心设计动机（`app.js:1631-1633` 注释）：**要保证所有内容在考试前走完所有轮次并毕业**，因此最后一批新内容最晚必须在 `deadline − cycleDays` 天学完。

### 2.2 三态是什么

复习队列里每条背书内容有 3 个按钮（`app.js:7316-7318`）：

| quality 值 | 背书文案 | 错题文案 | 快捷键 |
|---|---|---|---|
| `good` | ✓ 记得 | ✓ 做对了 | 1 |
| `fuzzy` | ~ 模糊 | ~ 看答案 | 2 |
| `forgot` | ✗ 忘记 | ✗ 又错了 | 3 |

录入表单里的三态按钮（`index.html:327-331`）默认文案就是"记得/模糊/忘记"，由 `renderStageOptions`（`app.js:5030-5040`）按类型切换。

### 2.3 三态间隔模型（核心，错题/背书共用）

`transitionReview`（`app.js:3592-3624`）——纯函数，Anki Again/Hard/Good 思路：

```js
function transitionReview(intervals, s0, wrongStreak0, quality, isFirstLearn, rollbackAfter){
  rollbackAfter = rollbackAfter || 2;
  const last = intervals.length - 1;
  const firstGap = intervals[0] || 1;
  if (isFirstLearn){                       // 首次学习
    let gap = firstGap;
    if (quality==='fuzzy') gap = Math.max(1, Math.round(firstGap*0.5));
    else if (quality==='forgot') gap = Math.max(1, Math.round(firstGap*0.3));
    return { stage:0, gap, wrongStreak: quality==='forgot'?1:0 };
  }
  const curGap = intervals[Math.min(s0,last)] || firstGap;
  if (quality==='good'){                   // 记得：进下一轮
    const stage = Math.min(s0+1, last);
    return { stage, gap: intervals[stage]||firstGap, wrongStreak:0 };
  }
  if (quality==='fuzzy'){                  // 模糊：也进轮，但间隔被压
    if (s0 >= last) return { stage:last, gap: Math.max(curGap+1, Math.round(curGap*1.3)), wrongStreak:0 };
    const stage = s0+1;
    const nextGap = intervals[stage] || curGap;
    const gap = Math.min(nextGap, Math.max(curGap+1, Math.round(curGap*1.3)));
    return { stage, gap, wrongStreak:0 };
  }
  // forgot：停留本轮，间隔回首轮；连续 rollbackAfter 次退一轮
  var wrongStreak = wrongStreak0 + 1;
  var stage = s0;
  if (wrongStreak >= rollbackAfter){ stage = Math.max(0, s0-1); wrongStreak = 0; }
  return { stage, gap: firstGap, wrongStreak };
}
```

**三态对应的间隔变化（默认间隔表）：**

| 状态 | stage 变化 | 间隔 gap |
|---|---|---|
| good（记得） | +1 轮 | 下一轮标准间隔（1→2→4→7→15→30） |
| fuzzy（模糊） | +1 轮 | `min(下一轮间隔, max(当前+1, 当前×1.3))` —— 薄弱内容不会被快速放到长间隔 |
| forgot（忘记） | 停留本轮；连续 2 次退 1 轮 | 回到首间隔（默认 1 天） |

**模糊态特殊处理**：在最后一轮仍模糊 → 不毕业，间隔只小幅拉长 `max(curGap+1, curGap×1.3)`（`app.js:3610-3612`）。

**连续忘记/记得**：连续 forgot 计数 `wrongStreak`，满 `lapseRollback`（默认 2）退一轮并清零；连续 good ≥3 次在 `getItemScore`（`app.js:3985-3990`）里给掌握度 +0.1。

### 2.4 scheduleNextReview 在背书下的完整行为（`app.js:3087-3159`）

```js
function scheduleNextReview(p, item, baseDate, stage, gapOverride){
  const intervals = getItemIntervals(item, p);
  const st = Math.min(stage ?? (item.stage||0), intervals.length-1);
  let gap = gapOverride || intervals[st] || intervals[0] || 1;
  if (item.earlyReviewed) gap = Math.max(1, Math.round(gap*0.85));  // 提前复习过→间隔缩15%

  // ★ 背书专属：冲刺期 clamp（app.js:3100-3116）
  if (p.type==='recite' && p.deadline){
    const d2d = diffDays(baseDate, p.deadline);
    if (d2d >= 0 && d2d <= getReviewCycleDays(p)){        // 距考试 ≤ 59 天
      const lastQ = item.reviews?.at(-1)?.quality ?? null;
      const capGap = d2d===0 ? 1
        : (lastQ==='good') ? Math.max(1, Math.min(d2d, Math.round(d2d*0.6)))
        : Math.max(1, Math.min(3, d2d));                  // 模糊/忘记→2~3天内再见
      gap = Math.min(gap, capGap);
      sprintClamp = d2d;
      if (d2d <= 7){                                       // 最后7天：均匀撒到剩余天
        sprintTail = true;
        if (lastQ!=='good' && addDays(baseDate,gap) >= p.deadline) sprintFinal = true;
      }
    }
  }
  if (sprintFinal){ item.finalReviewDate = baseDate; return addDays(p.deadline,1); }

  // 低频题降频（app.js:3124）：recite 也吃（type!=='exercise'），但 UI 开关在策略条里（见 §8 P1-02）
  if (p.lowFreqExtended && p.type!=='exercise'){ ... gap = Math.min(maxGap, round(gap*1.5)); }

  const base = addDays(baseDate, gap);
  if (p.reviewMode==='balanced' && p.type!=='exercise'){   // 均匀模式错峰
    let maxForward, maxBack, maxExtend;
    if (sprintTail){ maxBack=1; maxForward=Math.max(0,sprintClamp-gap); maxExtend=0; }
    else {
      maxForward = Math.max(1, Math.round(gap*0.25));
      maxBack = Math.min(2, Math.floor(gap*0.25));
      maxExtend = gap<=2 ? 3 : 14;                          // 早期复习不推太远
      if (sprintClamp!=null) maxExtend = Math.min(maxExtend, sprintClamp);
    }
    let d = findAvailableDate(p, base, {maxForward,maxBack,minDate:addDays(baseDate,1),gap,maxExtend});
    if (p.deadline && p.deadline>=todayStr() && d>p.deadline) d = p.deadline;  // ★ 只在 deadline 未过期时 clamp
    return d;
  }
  if (p.deadline && p.deadline>=todayStr() && base>p.deadline) return p.deadline;
  return base;
}
```

**关键 clamp 行为**：
- 冲刺期（距考试 ≤ cycleDays=59 天）：good 间隔压到 `d2d×0.6`，fuzzy/forgot 压到 ≤3 天，保证考前高频复现。
- 最后 7 天（sprintTail）：把复习均匀撒到 `[明天, 目标日]`，不堆到目标日。
- **deadline 已过期（< today）时不 clamp**（条件 `p.deadline >= todayStr()`）——新复习按自然间隔排到未来，符合"目标日已过，做多少算多少"。

### 2.5 balanced（均匀）vs classic（经典）在背书下的差异

| | classic 经典间隔 | balanced 均匀分布 |
|---|---|---|
| 排期 | 严格 `baseDate+gap` | `findAvailableDate` 在 `[base-2, base+gap×0.25]` 找负载最低日 |
| 错峰 | ❌ | ✅（`app.js:3133-3156`） |
| 今日超额 | 不自动摊，显示手动"分散"按钮 | `autoBalanceIfNeeded` 自动摊到未来 |
| 切换时 | 逾期如实显示，不推 | `rebalanceAllItems` 把未来条目错峰（`app.js:2448`） |

背书默认 `reviewMode='balanced'`（`app.js:11819-11821`）。

## 3. 舒适量与容量

### 3.1 默认值
```js

```
背书单条内容量大（十几页）→ 默认舒适量 **6**；错题默认 10。

### 3.2 读取与使用
```js
// app.js:2611  舒适量 = spreadThreshold，clamp 1..50
function getComfortCap(p){ return Math.max(1, Math.min(50, parseInt(p.spreadThreshold,10) || defaultComfortCap(p))); }
```

### 3.3 实际排题上限 = min(舒适量, 容量) 是否对背书生效
- **固定容量模式（dailyCapacity 设了数字）**：✅ 生效。`getSpreadDayCap`（`app.js:2691-2693`）返回 `min(舒适量, dailyCapacity)`；配置矛盾提示 `renderConfigWarnBar`（`app.js:6881`，`dailyCapacity>舒适量` 时弹条）对背书也生效。
- **智能模式（dailyCapacity=null）**：❌ **不以舒适量封顶**。`getDailyCapacity`（`app.js:2769-2770`）硬顶 50，今天用 `max(舒适量, cap)`（`app.js:2696`）。即智能模式下背书某天可以排超过舒适量 6 条，由状态卡温和提示，不硬卡。

### 3.4 固定容量模式对背书是否可用
✅ 可用。设置页 `#sCapacityMode`（`index.html:856`）选"固定数量"，`#sCapacityFixed` 填数（0=严格不错峰）。`app.js:10138-10140` 回填。

### 3.5 冷启动速率（背书 vs 错题）
`getDailyCapacity`/`getEwmRate`（`app.js:2738-2747`、`3452-3456`）：
- 活跃日<3：背书 rateCap=**4**（错题 5）
- K0：背书 **5**（错题 8）；PRIOR：背书 **4**（错题 6）
- 积压追赶 `catchDays`：背书 **10 天**（错题 7 天，`app.js:2707`）

## 4. 新内容收录与掌握判定

### 4.1 新内容怎么添加
**仅手动逐条添加**（`#btnReciteAdd`，`app.js:13043`）：填内容 + 页码区间 + 选三态 + 学习日期。**无批量导入**（对比：刷题本有 records 批量，错题本也无批量）。
- 页码必填（`app.js:13066`）：单页填一个，范围填起止。
- 三态必选（`app.js:13082`）。
- 录入时首个 gap 用 `gapForQuality`（`app.js:13086`）。

> ⚠️ **P1-01 录入不错峰**：`app.js:13116-13124` 只有 `isMistake && reviewMode==='balanced'` 才走 `findAvailableDate` 错峰；**背书一律走 else → `nextReviewDate = addDays(date, gap)`**。默认 `intervals[0]=1` 时 good/fuzzy/forgot 都排到"明天"，批量录入会全堆在同一天，要等它们到期那天才被 `autoBalanceIfNeeded` 摊开。

### 4.2 "掌握"（isMastered）怎么流转
`applyReview`（`app.js:3681-3760`）：
- 只有 **good 走到最后一轮**才考虑毕业（`app.js:3726`）。
- 最后一轮 good + reviews≥3 + 最近 3 次全 good → **直接毕业**：`mastered=true`、`masteredDate=today`、`nextReviewDate=null`、`scheduleRetention`（`app.js:3727-3732`）。
- 最后一轮 good 但不满足上述 → 弹"确认掌握了吗"窗（`app.js:3734-3747`）。
- fuzzy/forgot **永不触发毕业**（`app.js:3749-3758`）。

### 4.3 掌握后怎么处理
- 自然毕业（`mastered=true`）：进入**保持期复习** `scheduleRetention`（`app.js:2263`），间隔 30/30/45/60 天（`app.js:2216-2221`），每日软上限 5 条、错峰 21 天。保持复习"还记得"→继续拉长；"模糊了"→追加一条 forgot 回炉（`applyRetentionReview`，`app.js:2290`）。
- 手动"已熟知"（`manualMastered=true`）：`nextReviewDate=null`、`clearRetention`（不安排保持复习），从复习列表消失，可在"学习记录"找回（`app.js:13324-13330`）。
- 两者都**移出 due/overdue 队列**（`getDueItems` `app.js:2206` 过滤 `mastered||manualMastered`），但不删除数据。

## 5. 统计与 UI

### 5.1 统计逻辑
- 进度：背书按 `已背页数/总页数`（`app.js:8941-8946`），页数来自 `getCompletedPages`（`app.js:1783`）合并 `items` 的页码区间。
- 今日状态 `getTodayStatus`（`app.js:8880-8892`）：背书=到期复习 + 新学页目标两段。
- 统计聚合（`app.js:8615-8833`）：`reciteNew`（新背条数）、`reciteReviews`（复习次数）。

### 5.2 渲染函数
背书**没有独立渲染函数**，全部复用 `renderReview(p)`（`app.js:6977`），内部按 `p.type==='recite'` 分支：
- 同日到期按**书页顺序聚簇**（`app.js:7219-7223`，避免页码跳跃混乱）。
- 三态按钮文案 记得/模糊/忘记（`app.js:7293-7295`）。
- 单元卡按"条目掌握度"（`app.js:7546-7547`）。

## 6. 过期与截止日

### 6.1 deadline 过期后各机制行为
- `scheduleNextReview`：**不 clamp**（`app.js:3153-3157` 要求 `deadline>=today`），新复习按自然间隔排未来。
- 冲刺 clamp（`app.js:3100`）：要求 `d2d>=0`，过期后不触发。
- `rebalanceForSprint`（`app.js:3172`）：`d2d<0` 直接 return。
- `getDeadlineLevelCap`（`app.js:2559-2560`）：`daysLeft<=0` 返回 0。
- 逾期横幅 `#overdueBanner`：过期后改温和文案"目标日已过，这些旧题做多少算多少"（`app.js:7034-7036`）。
- 过期横幅 `renderDeadlinePassedBanner`（`app.js:6523`）：背书显示（type!=='exercise'），有"重设目标日/一键重排旧题/继续/归档"。

### 6.2 过期提示对背书是显示还是隐藏
**显示**（`app.js:6526` 只排除 exercise）。但文案硬编码"这本错题本"（`app.js:6563`）——见 §8 P2。

### 6.3 与 mistake 的差异
- mistake 有 `hardDeadline` 考试结束文案 + 归档导向；背书 `hardDeadline` 无调度意义。
- mistake 过期后 `rebalanceExpiredItems`（`app.js:3532`）把停在过去的题摊未来；背书同样可用（type!=='exercise'）。

## 8. 现有问题清单（按严重程度分级）

### 🔴 P1（设计缺口，影响排期质量）

**P1-01　背书录入时不走错峰，批量录入堆同一天**
- 位置：`app.js:13116-13124`
```js
if (isMistake && p.reviewMode === 'balanced') {
  newItem.nextReviewDate = findAvailableDate(p, firstBase, {...});  // 只有错题错峰
} else {
  newItem.nextReviewDate = firstBase;   // 背书一律 raw = date+gap
}
```
- 后果：背书用户连续录 10 条，默认间隔 1 天时全部排到"明天"，明天 due=10，要等明天渲染时 `autoBalanceIfNeeded` 才摊开。错题在录入瞬间就错峰了。
- 建议：背书 balanced 分支也走 `findAvailableDate`（与错题对齐）。

**P1-02　琥珀色策略条对背书是死代码 → 背书缺"战略性后置/暂停新学/低频降频"入口**
- 位置：`renderTightStrategyBar` `app.js:6775-6778`
```js
if (!p || p.type==='exercise' || p.archived) return;
...
const fe = getMistakeFeasibility(p);   // 背书永远 {level:'ok'}
if (fe.level === 'ok') return;          // ← 背书在这里直接 return，策略条永不渲染
```
- 后果：策略条上的「优先高频薄弱题(tacticalPostpone) / 暂停新题收录(pauseNewCollection) / 低频题降频(lowFreqExtended)」三个按钮**背书用户永远看不到**。
- 但 `lowFreqExtended` 在 `scheduleNextReview`（`app.js:3124`）对背书**生效**（`type!=='exercise'`）——即背书有这个排期能力，却没有任何 UI 能打开它。
- 建议：要么给背书独立的策略入口，要么在背书可行性（基于 newLearnEnd/cycleTight）上真正算 `fe`，让策略条活过来。

### 🟡 P2（文案/死代码/双实现漂移，不阻断但应修）

**P2-01　过期横幅/身后排队文案硬编码"错题本/错题"**
- `app.js:6563` "这本错题本陪你走过了备考的日子" —— 背书项目显示这句很违和。
- `app.js:6968` "最近每天新收约X道…错题会越攒越多" —— 背书应说"条/背书"。
- `app.js:6990-6992` honestHint 两个分支文案完全相同（`p.type==='mistake'` 三元两边一样），是残留。

**P2-02　`hardDeadline` 复选框对背书可见但无调度意义**
- 迁移只对 exercise 补 `hardDeadline`（`app.js:320`）；但设置页 `app.js:10209-10210` 把该行 `display` 永远设 `''`（两个分支都是 `''`），背书用户能勾选，却几乎不影响背书排期。

**P2-03　录入 gap（gapForQuality）与复习 gap（transitionReview.isFirstLearn）是两份平行实现**
- `gapForQuality`（`app.js:5011-5017`）：fuzzy=`round(first/2)`、forgot=`1`、good=`first`。
- `transitionReview` 首学分支（`app.js:3596-3602`）：fuzzy=`round(first*0.5)`、forgot=`round(first*0.3)`。
- 默认间隔 first=1 时两者都=1，看似一致；**但用户自定义间隔把 first 调大后，两处 forgot 口径（1 vs round(first*0.3)）会漂移**。建议统一调用。

**P2-04　设置页"💡错题本使用指南"按钮对背书可见**
- `#btnShowMistakeGuide`（`index.html:852`）在 `#reviewModeSection` 内，该 section 对背书显示，代码中**没有按 recite 隐藏它**（仅 `app.js:12112` 绑了打开事件）。背书用户点开会看到错题本指南。

**P2-05　死 CSS：`.recite-grid`（非 -2 版本）无对应 DOM**
- `style.css:379` 定义 `.recite-grid`，移动覆盖 `style.css:404-409`；但 index.html 只用 `recite-grid-2`（`index.html:283,301`），`.recite-grid`（裸类）无元素使用。

**P2-06　`getComfortCap(p, today)` 多传了第二个参数**
- `spreadOverdueItems`（`app.js:2330`）、`spreadExcessToday`（`app.js:2429`）调用 `getComfortCap(p, today)`，但 `getComfortCap(p)` 签名只接收 `p`（`app.js:2611`）。第二参数被静默忽略，无害但易误读。
