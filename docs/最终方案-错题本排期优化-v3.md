### BUG-05：sprintCap被comfort压回comfort，临时加量不生效
→ **[v3修复]** 冲刺期排题上限直接用 `sprintCap`，comfort临时失效。**且智能模式和固定模式都要接线。**

```js
// getSpreadDayCap(p, date) 完整修改（app.js:2670-2687）：
function getSpreadDayCap(p, date) {
  const comfort = getComfortCap(p);
  const today = todayStr();
  const isToday = (date === today);

  // [v3] 冲刺期全局判断：无论智能还是固定模式，sprint期每日目标抬到sprintCap
  if (p.sprintCap && p.sprintEndDate >= today) {
    // 清完积压后自动回落（在每日初始化时检查 backlog < comfort → 清除sprintCap）
    if (isToday) return Math.max(1, p.sprintCap);
    // 未来日也用sprintCap作为dayPlan.target的基准
    return Math.max(1, p.sprintCap);
  }

  if (p.reviewMode !== 'balanced') return comfort;
  if (p.dailyCapacity === 0) return comfort;
  if (p.dailyCapacity != null) {
    return Math.max(1, Math.min(comfort, Math.round(p.dailyCapacity)));
  }
  const cap = getDailyCapacity(p, date);
  if (cap <= 0) return comfort;
  if (isToday) return Math.max(comfort, cap);
  if (p.type === 'mistake') return getMistakeDayPlan(p, date).target;
  return Math.max(1, Math.min(50, cap));
}
```

**[v3关键修复]** sprintCap对智能模式也生效——在 `getSpreadDayCap` 最前面加全局判断，不分智能/固定分支。智能模式用户点"启动追赶"后，每日目标真的会变成sprintCap=P75，而不是写个没人读的字段。

**自动回落逻辑**（每日初始化时，如 `renderReview` 开头）：
```js
if (p.sprintCap && p.sprintEndDate) {
  const backlog = getOverdueItems(p).length;
  if (backlog < getComfortCap(p) || today > p.sprintEndDate) {
    p.sprintCap = null;
    p.sprintEndDate = null;
    saveStore();
  }
}
```

## 三、方案A最终设计

### 3.1 smartCap来源拆解

```
smartCap = max(EWMA, backlogCatchUp, deadlineLevelCap, weekdayAware)
getSmartCapSource(p, date) → { source, value, all }
```

**[v3关键概念区分]**：
- **"smartCap四来源谁最大"** → 判断压力来源（是deadline逼的？还是用户节奏快？还是积压？）
- **"背上有没有逾期债"** → 判断该不该给追赶按钮
- 这是**两个独立信号**，不能混为一谈。

### 3.2 建议分支矩阵（v3重写A2触发条件）

| 分支 | 触发条件 | 建议方向 |
|------|---------|---------|
| **A1: EWMA主导-建议调高舒适量** | 智能模式 + smartCap来源=EWMA + smartCap>comfort + 距deadline>30天 + feasibility≠risk + 连续低迷<21天 + 当天未弹 | 建议调高舒适量到 `min(EWMA, 25)`，不低于默认值10 |
| **A2: 有逾期债-追赶节奏** | **[v3修复]** 智能模式 + **backlog > comfort（真有逾期债）** + **consecutiveLowDays < 21（短期低迷，不是长期低能）** + **feasibility ≠ risk（临考risk走琥珀色策略条，不走追赶）** + 当天未弹 | 显示"追赶节奏"按钮（见3.3节） |
| **A3: deadline主导-中性说明** | smartCap来源=deadline + feasibility≠ok | #excessAdvice只显示中性说明"今天的量主要来自截止日追赶"，**不显示"看看能否后移"按钮**。后移建议统一由琥珀色策略条负责。 |
| **A4: 固定模式-配置矛盾** | 固定模式 + dailyCapacity>comfort + 连续3天排题=comfort + 当天未弹 | 独立中性提示条，二选一按钮 |
| **A5: 固定模式-考前加速** | 固定模式 + 距deadline≤30天 + feasibility=risk | 临时加量建议，suggestCap封顶 `dailyCapacity+4` |
| **A6: 固定模式-早期容量校准** | 固定模式 + 连续14天轻松完成（用时短、正确率稳、无逾期）+ 当天未弹 | 设置页容量框旁灰字建议，**[v3] 建议值算式写死为 `min(dailyCapacity + 3, 10)`** |

**为什么A2不再依赖smartCap来源=backlog？**
冲刺期用户backlog=35→need=5，而EWMA≈8-9、deadlineLevel≈20，最大值是deadlineLevel。如果按"smartCap来源=backlog"判断，永远判成A3，追赶按钮永远不亮。
**正确逻辑**：追赶按钮的触发条件是"你背上有逾期债 + 你是短期低迷（不是真低能）+ 还没到临考risk"。smartCap来源拆解只用来判断A3（deadline主导），不影响A2。

### 3.3 A2追赶节奏按钮（v3修订）

**文案：**
```
💡 你已累计积压 {backlog} 条，距目标还剩 {daysLeft} 天。
   从明天起按你平时的节奏每天 {P75} 条，约 {K} 天清完积压并回到正轨，来得及。
   
   [按每天{P75}条启动追赶]   [就维持现状]   [✕]
```

**按钮行为**：
- "启动追赶" = 设置 `p.sprintCap = P75` + `p.sprintEndDate = today + K天`（K=ceil(backlog/P75)）
- **[v3修复]** sprintCap对智能模式和固定模式都生效（BUG-05已修复全局接线）
- 清完积压后（backlog < comfort）自动清除 sprintCap/sprintEndDate（见BUG-05自动回落逻辑）
- "维持现状" = 当天关闭，不做任何修改

**低迷期文案补充**：
- 当 `consecutiveLowDays < 21` 时，额外加一句："最近两周你的节奏比平时慢一些，这是正常波动。你之前长期稳定在每天 ~{P75} 条，保持现有舒适量，先把积压清回来。"

### 3.4 当日完成量抑制规则（v3修订）

**当用户当天完成量 ≥ 历史P75 × 0.9 时：**
- **suppress**：excessBanner档位3（积压警告）、backlog提示、"落后/积压"类负面提示
- **[v3修订] 不suppress**：A1正面建议行（"调高舒适量到X条"）——这是正面建议，不是负面警告，用户状态好时更应该看到

```js
const suppressNegatives = todayCompletedCount >= getHistoricalP75(p, 60) * 0.9;
// if (suppressNegatives) → 跳过 excessBanner档3 / backlog提示 / risk警告
// A1调高舒适量建议 → 不管suppressNegatives，照常显示
```

### 3.5 D1决策：低强度用户严格条件下允许建议调低

**触发条件（全部满足）：**
1. 连续21天以上完成量 < comfort × 0.7
2. backlog稳定或下降（不增长）
3. 距deadline > 30天
4. `p.hardDeadline !== true`
5. 当天未弹过

**建议值：** `max(5, Math.round(EWMA))`

due=0时显示"今天已完成 {doneCount} 条，状态不错？再从未来待复习里拉 {N} 条"，N=min(5, 未来14天薄弱题数)。

## 四、方案C最终设计

### 4.1 过期提示

**触发条件**：deadline < today + 有未掌握 + 未归档 + 当天未关闭 + 从用户第一次实际打开过期项目开始算前3天。

**普通过期（hardDeadline=false或未标记）：**

| 过期程度 | 主文案 | 按钮 |
|---------|--------|------|
| 刚过期（首次打开后≤3天） | 📌 目标日刚过去，还有 **{N}** 条未完成 | ①重设目标日 ②一键重排旧题 ③继续不赶进度 ④归档 |
| 过期较久（>3天） | 📌 目标日已于 {date} 到期，还有 **{N}** 条 | ①重设目标日 ②继续不赶进度 ③归档 |

**[v3新增] hardDeadline=true且已过期（考试日截止用户）：**

| 主文案 | 按钮顺序 |
|--------|---------|
| 📚 考试已经结束了。这本错题本陪你走过了备考的日子。 | **[归档这本]**（主按钮，琥珀色实心）/ [准备二战，重新设目标] / [以后再说] |

理由：对考试日用户，过期=战役结束，不是"目标没达成"。主按钮是归档（翻篇），不是重设目标。

**"一键重排旧题"行为**：`rebalanceExpiredItems(p)`，把 nextReviewDate ≤ today 且 `canBeSpread=true` 的题按正常间隔摊到未来。**[v3修订]** canBeSpread=false的锁死题不硬摊（尊重防饥饿规则）。

**"继续不赶进度"行为**：
- 记录 `p.deadlineWarnDismissedDate = today`
- 同时触发 `rebalanceExpiredItems(p)`（存量重排）
- 之后每7天（时间戳判断）弹一次
- 每周弹那次多放极小文字链 **"不再提醒"**（`p.deadlineMuted = true`）

**归档行为**：
- `p.archived = true`，从首页/项目列表隐藏
- 同时停止retention（不再纳入任何复习统计/广场数据）
- 归档有撤回路径：首页"已归档"收纳箱，每个项目有"取消归档"按钮

### 4.2 偏紧阶段建议

**核心**：smartCap来源=deadline且feasibility≠ok时，**不显示红色判决横幅**，只用琥珀色策略建议条。

**琥珀色策略条内容（优先级从高到低）：**

```
💡 [根据累计弹次选择文案]

你的复习任务偏紧。以下是可以优化的方向：

【第一优先：优化复习策略】
  ① 优先高频薄弱题：先做最高频+最不熟的{mustDo}条
  ② 暂停新题收录：临考期先不往错题本加新题
  ③ 低频题降频：偏题怪题拉长间隔，考前随缘看一眼
  
【第二优先：调整节奏】
  ④ [条件显示] 如果不是hardDeadline：后移到 {suggestedDate}，每天少做 {gap} 条
  
  [按钮1: 先做高频薄弱题]  [按钮2: 暂停新题]  [按钮3: 后移日期]  [✕]
```

**[v3修订] "后移日期"按钮行为**：
- **一键自动改deadline为suggestedDate**，不跳设置页
- 改完后立即触发 `rebalanceExpiredItems`（如果有过期题）+ 重排未来日程
- 用户看到的效果：点一下，日期变了，每天量自动降下来

**[v3新增] 首次点"后移日期"时的引导：**
用户第一次点"后移日期"按钮时，在按钮上方弹出一行小灰字：
"你的截止日是考试日吗？如果是，建议在设置页勾选「硬约束」，以后系统就不再建议后移了。"
（不阻断操作，只是轻提示引导勾选hardDeadline）

**hardDeadline=true时**：完全不显示按钮3"后移日期"。

**suggestedDate计算**：
```js
const effectiveDaily = Math.max(getComfortCap(p), getEwmRate(p));
const neededDays = Math.ceil(totalWork / effectiveDaily);
const suggestedDate = addDays(today, neededDays);
```

**文案递进机制**：
| 累计弹次 | 文案语气 |
|---------|---------|
| 第1次 | 邀请式："最近任务有点紧，要不要看看怎么调整？" |
| 第3次 | 确认式："你已经连续几天任务偏多了。如果目标日不是硬约束，后移会舒服很多。" |
| 第7次+ | 最短式："任务偏紧。[优化策略] [后移日期]" |

**mistakeRiskBanner降频**：
- 每周最多弹1次（时间戳判断）
- smartCap来源=deadline时，完全不显示红色mistakeRiskBanner
- smartCap来源=EWMA或backlog时，保留红色横幅

### 4.3 临考期提示合并
多条提示合并成一行（见v2），不再一屏4个盒子。

### 4.4 pullForward说明文案
"这 {N} 道原定于后面几天，为赶考试提前到今天；对应后面几天会少这些。"

### 4.5 overdueBanner过期后文案改写
"📌 还有 {N} 道旧题停在 {旧目标日}，做多少算多少。"
或点"继续不赶进度"并完成存量重排后自然消失。

## 五、排期算法优化清单

| # | 算法 | 修改内容 |

## 六、边界情况矩阵

| 用户 | 场景 | 系统表现 |
|------|------|---------|
| 高强度智能 | due=16, EWMA主导 | 中性信息条"今日安排16条"；建议行"调高舒适量到16"（当日完成高时也显示）；due=0时"再拉5条" |
| 低强度智能 | due=15, backlog=10 | 积压横幅"正常到期5条+逾期10条"；不建议调低（未达21天）；"今天就到这"在列表上方；pullForward不拉 |
| 低强度-达条件 | 21天低产能+backlog稳定 | 建议调低到max(5,EWMA)，配"状态好再往上加" |
| 固定容量低 | cap=5, comfort=10, due=5 | 无横幅；"身后N题排队"灰字；考前≤30天risk时弹"临时+4条"；设置页旁校准灰字（建议min(cap+3,10)） |
| 固定容量高 | cap=20, comfort=10, due=10 | 独立中性提示条"你设了20但舒适量10限制排到10"；按钮2文案"改成{comfort}条，匹配我最近实际节奏" |
| 临考积压 | <30天, risk, smartCap=deadline | 不显示红色判决横幅；琥珀色策略条（优化策略优先）；临考三按钮；提示合并一行 |
| 已过期 | deadline过5天, 23条未掌握 | 琥珀色过期banner；按钮含一键重排；复习一道不再制造新逾期；rebalance尊重锁死题不硬摊 |
| 已过期-hardDeadline | 考试日过了, hardDeadline=true | 文案"📚 考试已经结束了。这本错题本陪你走过了备考的日子。"；主按钮=归档这本 |
| 冲刺期低迷 | P75=12, 最近7天5-6, backlog=35 | **[v3修复]** 显示追赶节奏按钮（因为backlog>comfort+低迷<21天，不依赖smartCap来源）；点启动后sprintCap=12对智能模式生效；当日完成≥10.8时suppress负面提示 |
| 截止日偏紧 | deadline设早了, smartCap=deadline, hardDeadline=false | 琥珀色策略条；"后移日期"按钮一键自动改deadline+触发rebalance；首次点时引导hardDeadline勾选 |
| 截止日偏紧-hardDeadline | 同上但hardDeadline=true | 琥珀色策略条只有优化策略按钮，完全不显示后移 |
