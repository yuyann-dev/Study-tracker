## 二、BUG修复清单

### BUG-01：scheduleNextReview 过期clamp制造新逾期
→ 同v1。app.js:3132/3135 加 `p.deadline >= todayStr()` 条件。
→ **[v2修订]** 存量迁移改为：过期banner首次出现时附"一键重排旧题"按钮；或用户点"继续不赶进度"时自动触发 `rebalanceExpiredItems(p)`（新增函数），把 nextReviewDate 停在旧deadline的题按正常间隔摊到未来。
→ **[v2修订]** rebalance触发时机：保存新deadline后检测到 `p.deadline` 从过去变为未来时触发，不是点按钮瞬间。

### BUG-02：超量横幅只看舒适量
→ 同v1三档逻辑。**[v2修订]** 档3横幅显式拆成两行数字："今日正常到期 {Y} 条 · 另有 {M} 条逾期待还"（Y=N-M，不让用户自己算）。

### BUG-03：getComfortAdvice死锁
→ 同v1。废弃设置页动态建议。

### BUG-04：**[v2新增]** 配置矛盾消息嵌在excessBanner内部导致永远看不到
| 项目 | 内容 |
|------|------|
| **根因** | 固定容量高用户 dailyCapacity=20, comfort=10，实际排题=min(10,20)=10=comfort。excessBanner触发条件是 due>comfort，而due=comfort时横幅不弹。配置矛盾消息嵌在横幅内部 → 用户永远看不到。 |
| **修复方案** | 配置矛盾消息改为**独立中性提示条**，用 `.ob-advice` 样式，在复习列表顶部独立渲染。触发条件：`p.dailyCapacity != null && p.dailyCapacity > getComfortCap(p)`，不依赖excessBanner是否弹出。 |
| **弹出频率** | 当天未关闭才显示；点✕后 `p.configWarnDismissedDate = today`。连续3天点✕ → 7天不再弹。 |

### BUG-05：**[v2新增]** sprintCap被comfort压回comfort，临时加量不生效
| 项目 | 内容 |
|------|------|
| **根因** | v1方案写 `getSpreadDayCap` 固定模式分支 `min(comfort, sprintCap)`。如果comfort=10, sprintCap=15，结果还是10——临时加量被舒适量吞掉。 |
| **修复方案** | 冲刺期排题上限直接用 `sprintCap`，**comfort临时失效**： |

```js
// getSpreadDayCap 固定模式分支修改：
if (p.dailyCapacity != null) {
  // [v2] 冲刺期：comfort临时失效，直接用sprintCap
  if (p.sprintCap && p.sprintEndDate >= todayStr()) {
    return Math.max(1, p.sprintCap);  // 不再min(comfort, sprintCap)
  }
  return Math.max(1, Math.min(comfort, Math.round(p.dailyCapacity)));
}
```

## 三、方案A最终设计（v2）

### 3.1 smartCap来源拆解（保留v1核心）

```
smartCap = max(EWMA, backlogCatchUp, deadlineLevelCap, weekdayAware)
新增 getSmartCapSource(p, date) → { source, value, all }
```

### 3.2 建议分支矩阵（v2重写）

| 分支 | 触发条件 | 建议方向 |
|------|---------|---------|
| **A1: EWMA主导-建议调高舒适量** | 智能模式 + smartCap来源=EWMA + smartCap>comfort + 距deadline>30天 + feasibility≠risk + 连续低迷<21天 + 当天未弹 | 建议调高舒适量到 `min(EWMA, 25)`，不低于默认值10 |
| **A2: backlog主导-追赶节奏** | 智能模式 + smartCap来源=backlog + backlog>comfort + 当天未弹 | **[v2重写]** 显示"追赶节奏"按钮，不是"稳步清完即可"（见3.3节） |
| **A3: deadline主导-不建议调高舒适量** | smartCap来源=deadline + feasibility≠ok | **[v2修订]** #excessAdvice只显示中性说明"今天的量主要来自截止日追赶"，**不显示"看看能否后移"按钮**。后移建议统一由琥珀色策略建议条负责（见方案C偏紧阶段）。 |
| **A4: 固定模式-配置矛盾** | 固定模式 + dailyCapacity>comfort + 连续3天排题=comfort + 当天未弹 | **[v2修订]** 独立中性提示条（不嵌excessBanner），二选一按钮 |
| **A5: 固定模式-考前加速** | 固定模式 + 距deadline≤30天 + feasibility=risk | 临时加量建议，suggestCap封顶 `dailyCapacity+4`（不给不切实际的数字） |
| **A6: 固定模式-早期容量校准** | **[v2新增]** 固定模式 + 连续14天轻松完成（用时短、正确率稳、无逾期）+ 当天未弹 | 设置页容量框旁灰字建议，不弹横幅 |

### 3.3 backlog主导分支："追赶节奏"按钮（v2重写冲刺期用户需求）

**文案：**
```
💡 你已累计积压 {backlog} 条，距目标还剩 {daysLeft} 天。
   从明天起按你平时的节奏每天 {P75} 条，约 {K} 天清完积压并回到正轨，来得及。
   
   [按每天{P75}条启动追赶]   [就维持现状]   [✕]
```

**按钮行为**：
- "启动追赶" = 设置 `p.sprintCap = P75` + `p.sprintEndDate = today + K天`（K=预计清完积压的天数）
- sprintCap对**智能模式也开放**（v2修订：不只给固定模式）
- 清完积压后（backlog < comfort）自动清除 sprintCap/sprintEndDate
- "维持现状" = 当天关闭，不做任何修改

**低迷期文案补充**：
- 当 `consecutiveLowDays < 21` 时，额外加一句："最近两周你的节奏比平时慢一些，这是正常波动。你之前长期稳定在每天 ~{P75} 条，保持现有舒适量，先把积压清回来。"
- **不**说"稳步清完即可"，要说"保持舒适量、先清积压"。

### 3.4 当日完成量抑制规则（v2新增）

**当用户当天完成量 ≥ 历史P75 × 0.9 时，当天suppress所有"落后/积压/超量"类提示。**
- 理由：用户已经在补救了，别再往伤口上撒盐。
- 实现位置：renderReview开头检查 `todayCompletedCount >= getHistoricalP75(p,60) * 0.9`，如果是，跳过 excessAdvice / backlog提示 / excessBanner档位3。

### 3.5 D1决策：低强度用户严格条件下允许建议调低（v2修订）

**触发条件（全部满足，缺一不可）：**
1. 连续21天以上完成量 < comfort × 0.7（真实低产能，不是短期波动）
2. backlog稳定或下降（不增长——说明真的消化不了系统排的量，而不是没做）
3. 距deadline > 30天（非临考）
4. `p.hardDeadline !== true`（非硬约束）
5. 当天未弹过

**建议值：** `max(5, Math.round(EWMA))`（不低于5，不高于当前comfort）

**文案：**
```
💡 你最近三周每天完成约 {EWMA} 条，当前舒适量 {comfort} 条偏多，
   每天的清单可能偏长。要不要调到 {suggest} 条？这样每天清单更短、更容易做完，做完就是今天的胜利。
   复习计划不变，只是每天少展示几条。状态好的时候可以再轻轻往上加。
   
   [调到{suggest}条]   [保持{comfort}条]   [✕]
```

**不满足条件时**：维持"不低于默认值10"，不弹调低建议。

### 3.6 pullForward刹车（v2新增）

**低强度用户保护**：当今日due已超过用户EWMA产能时，不再把未来题硬拉来。

```js
// pullForwardIfNeeded 新增前置判断：
const ewma = getEwmRate(p, today);
if (getDueItems(p).length > ewma * 1.2) return 0;  // 今天已经超了，别再拉了
```

### 3.7 主动加量入口（v2新增，高强度用户需求）

**当复习列表清空后（due=0，当天还有未完成的复习额度）：**
- 列表位置显示小灰字："今天已完成 {doneCount} 条，状态不错？再从未来待复习里拉 {N} 条"
- N = min(5, 未来14天内到期的薄弱题数)
- 点击 → 走 pullForwardIfNeeded 同款逻辑（从未来14天挑薄弱题提前到今天）
- 拉上来的题正常走间隔算法

### 3.8 固定模式独立可行性计算（v2新增）

`getMistakeFeasibility` 中，固定模式的判定基准改为**实际排题量**：
```js
// 固定模式：实际每天排题 = min(comfort, dailyCapacity)
// 用这个值作为"每天能做多少"的基准，而不是comfort或hardMax
const effectiveDaily = (p.dailyCapacity != null) 
  ? Math.min(getComfortCap(p), p.dailyCapacity)
  : Math.max(getComfortCap(p), getEwmRate(p));
```
效果：固定容量低用户（cap=5），当剩余工作量 > 剩余天数×5 时就报警"做不完"，不再用comfort=10假装来得及。

### 3.9 "身后N题排队"具体设计（v2新增）

**位置**：复习列表上方、banner区域之下，一行小灰字。
**数字口径**：`behindCount = getDueItemsInFuture(p).length`（未来7天内排队的复习题总数）
**何时变红**：behindCount > 舒适量 × 5 时文字变红
**文案**："除今天 {todayDue} 题外，未来7天还有 {behindCount} 题排队中"

### 3.10 "+3题加练"小按钮（v2新增）

**位置**：复习列表底部（非临考期）
**文案**："+ 再排3题"
**行为**：从未来14天挑3道薄弱题提前到今天（走pullForward逻辑），标记earlyReviewed
**临考期**：隐藏（避免加重负担）

### 3.11 设置页实时反馈（v2新增）

**dailyCapacity输入框旁**实时显示：
```
当前舒适量 {comfort} 条，实际每天排题 = min({comfort}, {capacity}) = {actual} 条
```
- 用户改capacity时，actual数字实时更新
- 当 capacity > comfort 时，这行文字变琥珀色提醒

**deadline输入框下方**加引导文案：
```
这个日期越近，系统每天排的复习题越多。建议比真实考试日留2~4周余量。
填错了随时可以改，系统会自动重排。
```

**hardDeadline勾选项**：deadline输入框旁加一个checkbox "此截止日为硬约束/考试日，不要建议后移"。勾选后 `p.hardDeadline = true`，永久关闭所有"后移截止日"建议。

## 四、方案C最终设计（v2）

### 4.1 过期提示（同v1 + v2修订）

**触发条件**：deadline < today + 有未掌握 + 未归档 + 当天未关闭 + **从用户第一次实际打开过期项目开始算前3天**（不从deadline日期算）。

**三档文案**（同v1，但按钮增加"一键重排旧题"）：

| 过期程度 | 主文案 | 按钮 |
|---------|--------|------|
| 刚过期（首次打开后≤3天） | 📌 目标日刚过去，还有 **{N}** 条未完成 | ①重设目标日 ②**[v2新增] 一键重排旧题（按间隔摊到未来）** ③继续不赶进度 ④归档 |
| 过期较久（>3天） | 📌 目标日已于 {date} 到期，还有 **{N}** 条 | ①重设目标日 ②继续不赶进度 ③归档 |

**"一键重排旧题"行为**：调用 `rebalanceExpiredItems(p)`，把 nextReviewDate ≤ today 且 canBeSpread=true 的题按正常间隔摊到未来。

**"继续不赶进度"行为**：
- 记录 `p.deadlineWarnDismissedDate = today`
- 同时触发一次 `rebalanceExpiredItems(p)`（存量重排）
- 之后改为每 **7天**（时间戳判断：上次展示日+7天，不绑星期几）弹一次
- 每周弹那次多放一个极小文字链 **"不再提醒"**（≠归档，只是 `p.deadlineMuted = true`，闭嘴不弹）

**归档行为**：
- `p.archived = true`，项目从首页/项目列表隐藏
- **同时停止retention**（不再纳入任何复习统计/广场数据）
- **[v2新增]** 归档有撤回路径：首页设"已归档"收纳箱，点进去看到已归档项目，每个有"取消归档"按钮

### 4.2 偏紧阶段建议（v2重大修订）

**核心变化**：红色mistakeRiskBanner与琥珀色建议条合并。当smartCap来源=deadline且feasibility≠ok时，**不显示红色判决横幅**，只用琥珀色策略建议条。

**琥珀色策略条内容（优先级从高到低）：**

```
💡 [根据累计弹次选择文案]

你的复习任务偏紧。以下是可以优化的方向：

【第一优先：优化复习策略】（永远排在最前）
  ① 优先高频薄弱题：从今天的{due}条里，先做最高频+最不熟的{mustDo}条
  ② 暂停新题收录：临考期先不往错题本加新题，集中清旧的
  ③ 低频题降频：偏题怪题拉长间隔，考前随缘看一眼
  
【第二优先：调整节奏】
  ④ [v2-条件显示] 如果不是hardDeadline：后移到 {suggestedDate}，每天少做 {gap} 条
  
  [按钮1: 先做高频薄弱题]  [按钮2: 暂停新题]  [按钮3: 后移日期]  [✕]
```

**hardDeadline=true时**：完全不显示按钮3"后移日期"。

**suggestedDate计算**（v2修订）：
```js
const effectiveDaily = Math.max(getComfortCap(p), getEwmRate(p));
const neededDays = Math.ceil(totalWork / effectiveDaily);
const suggestedDate = addDays(today, neededDays);
```

**文案递进机制**（v2新增）：
| 累计弹次 | 文案语气 |
|---------|---------|
| 第1次 | 邀请式："最近任务有点紧，要不要看看怎么调整？" |
| 第3次 | 确认式："你已经连续几天任务偏多了。如果目标日不是硬约束，后移会舒服很多。" |
| 第7次+ | 最短式："任务偏紧。[优化策略] [后移日期]" |

**mistakeRiskBanner降频**（v2新增）：
- 从"每天打开都弹"改为"每周最多弹1次"（时间戳判断）
- 当smartCap来源=deadline时，**完全不显示红色mistakeRiskBanner**，由琥珀色策略条替代
- 当smartCap来源=EWMA或backlog时，保留红色横幅（说明用户确实能力不足，不是deadline问题）

### 4.3 临考期提示合并（v2新增）

临考期（≤30天+risk）多条提示合并成一行：
```
┌─────────────────────────────────────────────────────────┐
│ 📋 今日 {Y} 条正常到期 · {M} 条逾期待还 · 为赶考试提前了 {N} 条 │
│    [先做高频薄弱{N}条]  [暂停新题]  [低频降频]  [✕]        │
└─────────────────────────────────────────────────────────┘
```
不再一屏4个盒子。中性信息条+deadline说明行+pullForward说明合并成这一行。

### 4.4 pullForward说明文案（v2修订）
```
这 {N} 道原定于后面几天，为赶考试提前到今天；对应后面几天会少这些。
```
明说后面会变少，不让用户猜。

### 4.5 overdueBanner过期后文案改写（v2新增）
过期后overdueBanner文案改为：
```
📌 还有 {N} 道旧题停在 {旧目标日}，做多少算多少。
```
或用户点"继续不赶进度"并完成存量重排后，overdueBanner自然消失（因为旧题都被摊到未来了，不再是逾期）。

## 九、决策点状态

| # | 决策点 | v2结论 |
|---|--------|--------|
| D1 | 低强度用户是否允许调低舒适量？ | **v2修订：严格条件下允许**（连续21天低产能+backlog稳定+非临考+非hardDeadline），降到max(5,EWMA) |
| D2 | 固定模式是否纳入建议？ | **纳入**（配置矛盾独立条 + 考前加速 + 早期校准 + 独立可行性） |
| D3 | deadline主导时是否转建议后移？ | **v2修订：后移不是首选**。首选是优化复习策略（优先高频薄弱/暂停新题/低频降频），后移是最后选项，且hardDeadline用户完全不显示 |
| D4 | 过期提示频率？ | 首次打开后前3天每天弹，之后每7天弹一次（时间戳判断），点"不再提醒"后永久闭嘴 |
