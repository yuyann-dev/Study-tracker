## 一、Top 3 痛点逐条验证

### 痛点 1：全局时间调度缺失（P0 级）

**痛点描述**（v1 评审原文）：
> AI 只能逐科给建议，不能做"此消彼长"的全局时间再分配。缺时间总量约束、缺优先级排序、缺时间让渡式调度。三科都落后时并列三张红牌，用户不知道先救谁。

**v2 对应设计**：

| v2 设计点 | 位置 | 具体内容 |
|---|---|---|
| 今日时间快捷输入 | F1.7（§3.1）、§4 | 输入框旁"⏱ 今天可学 __h" chips（1h/2h/4h/全天），规划类意图必带；画像 `habit.dailyAvailableMin` 自动推断，用户可覆盖 |
| 全局时间守恒调度算法 | §11.2（重写为 P0） | 6 步算法：①输入 `budgetMin` → ②单位统一折算分钟 → ③ROI 打分 0-10 → ④时间守恒分配（总和=budgetMin，超前科降速让渡、落后科加时）→ ⑤认知交替排时间块 → ⑥输出 P0/P1/P2 |
| 此消彼长示例 | §11.2 输出示例 | "英语已超前，从 2h 降到 40min，省出的时间给数学和政治"——附带一组 `adjust_daily_capacity`（有升有降） |
| Prompt 硬约束 | §8 | "规划类建议必须先尊重用户给的今日时间预算，此消彼长、总量守恒；宁可说'今天只能做这 3 件'，也不要列一堆做不完的任务" |
| 今日时间块接口 | §6.2 `/api/ai/today?budgetMin=` | 本地算骨架，AI 仅润色，零/低 token |

**验证结论：✅ 已解决（核心架构到位，有细节缺口）**

v2 从架构上彻底重写了 §11.2，从"逐科速率 gap 报告器"升级为"硬约束下的全局时间调度器"：
- ✅ 用户能输入每日总时间预算（F1.7 chips + 画像推断，双保险）
- ✅ 各科分配此消彼长（§11.2 第 4 步明确"总和=budgetMin，超前科降速让渡"）
- ✅ P0/P1/P2 分级输出（解决"三张红牌并列"问题）
- ✅ 认知类型交替排块（回应了用户一"刷题/背书交替"的建议）

**遗留缺口（不影响核心可用，但影响精细度）：**
1. **ROI 打分的具体权重公式未给出**：§11.2 第 3 步列了 4 个因子（落后幅度、分值权重、边际收益、紧迫度），但没说每个因子占多少分、怎么合成 0-10 分。实现时可能拍脑袋。建议补一个显式的加权公式或至少给出默认权重表。
2. **没有"时钟时间轴"**：v1 用户一强烈要求"从早到晚的时间轴（9:00-11:30 数学…）"，v2 只输出"数学 50min / 政治 25min"这种时间块，没结合 `peakTime` 画像排到具体钟点。当前颗粒度可用但不够直观。
3. **时间块冲突处理未细化**：如果某天有套卷（固定 3h）+ 到期背书 + 错题复盘，三者时间块怎么自动避让？只说了"认知交替"，没说硬冲突（如套卷必须上午）怎么处理。

### 痛点 2：同科目多模块数据没打通

**痛点描述**（v1 评审原文）：
> 错题诊断只在 mistake 项目内做，不关联同科目下的刷题和背书项目。同一门专业课挂三个项目（刷题/背书/错题），AI 各说各话，用户看不到"这门课整体哪里弱"。

**v2 对应设计**：

| v2 设计点 | 位置 | 具体内容 |
|---|---|---|
| 科目级热力图 | §11.7（新增）、F7.4 | 按 `subjectKey` 把同科 exercise+recite+mistake 按章节树对齐，每叶子章输出三指标：刷题完成率 / 错题密度 / 背书掌握率 |
| 热力图接口 | §6.2 `/api/ai/subject-heatmap?subjectKey=` | 返回每叶子章 `{unitName, exerciseDoneRate, mistakeDensity, reciteMasteryRate}`，纯本地算 |
| 科目级聚合器 | §7.2 第 2 条 | `aiDataAggregator.js` 扩展科目维度聚合函数 |
| 跨项目 action | §9.1 `add_mistake_from_exercise` | 从刷题项目某页/题号范围批量抽错题为错题（v1 用户二强烈要求） |
| 同知识点联动提示 | §11.7 | 今日计划里提示"同一知识点的 3 条背书 + 2 道错题建议一起复习"，避免一天复习两遍 |
| subjectKey 字段 | §0.2、§5.3 | 项目级新增 `subjectKey` 字段（math/english/politics/major1...），用于跨项目聚合 |

**验证结论：✅ 已解决（数据打通到位，排期联动为提示级）**

- ✅ 科目级热力图（§11.7）完全回应了 v1 用户二"科目级薄弱章节热力图"的诉求——三指标叠加、按章节对齐、纯本地计算。
- ✅ `add_mistake_from_exercise` action 补上了"刷题→错题"的数据通道。
- ✅ `subjectKey` 字段是跨项目聚合的基础设施，设计合理。
- ✅ "同一知识点建议一起复习"回应了 v1 用户三"英语真题+作文协同"和用户二"背书+错题排期联动"的诉求。

**遗留缺口：**
1. **SRS 排期只是"提示一起复习"，没有真正合并排期**：v1 用户二要求"背书 item 和错题 item 共享知识点映射，合并到期条目一次性复习"。v2 做到了"提示一起复习"，但没有真正修改 SRS 调度器把同一 tag 的条目合并到同一天到期。这是体验上的差距——用户看到提示后还是要自己手动安排。建议后续版本做 tag 级排期合并。
2. **`subjectKey` 的推断逻辑未说明**：PRD 说"多数情况由 AI 推断"，但没说推断规则——是从项目名匹配？还是模板自动带？如果用户建了一个项目叫"专业课背诵"，AI 怎么知道它属于 major1？建议补一条推断规则说明。

### 痛点 3：日量单位不可比（页/条/套）

**痛点描述**（v1 评审原文）：
> 数学日量是"页/天"，政治背书是"条/天"，英语真题是"套/周"。AI 说"数学调 5 页、政治调 3 条"，用户不知道这要花多少时间。

**v2 对应设计**：

| v2 设计点 | 位置 | 具体内容 |
|---|---|---|
| minutesPerUnit 字段 | §0.2、§5.3 | 项目级新增 `minutesPerUnit`（float），每单位（页/条/套）预计分钟数，用户可改 |
| 自动推断逻辑 | §4 时间画像 | 从历史 records 时间戳差滑动平均估算；无时间戳则给经验默认（数学页 6-8min、英语套 180min、政治条 3min） |
| 统一折算分钟 | §7.2 第 3 条 | "所有建议日量统一乘 minutesPerUnit 得分钟，action 标签显示'约 X 分钟'" |
| 时间成本接口 | §6.2 `/api/ai/time-cost?projectId=` | 返回该项目 minutesPerUnit 推断值 + 历史样本数 |
| action 标签带时间 | §9.1 | `adjust_daily_capacity` 标签显示"约 X 分钟"；`create_review_list` label 含"N 条·约 X 分钟" |
| 输出示例 | §11.1、§11.2 | "今天只做这 4 道 = 50 分钟"、"政治马原复习 8 条 = 25min"——全部折算成分钟 |

**验证结论：✅ 已解决**

这条痛点解决得最彻底：
- ✅ 有数据模型字段（`minutesPerUnit`）
- ✅ 有自动推断逻辑（历史时间差 + 经验默认兜底）
- ✅ 有统一折算规则（所有建议乘 minutesPerUnit）
- ✅ 有接口（`/api/ai/time-cost`）
- ✅ action 标签和输出示例都带"约 X 分钟"

v1 用户一"建议每个项目加页均/条均耗时推断"的诉求完全落地。

**小缺口**：
- `minutesPerUnit` 是"每单位"的平均耗时，但套卷的 sections 耗时差异很大（选择 vs 大题），目前只支持项目级单值。v2 套卷 records 已有 `sections[].timeSpentMin`，但 `minutesPerUnit` 没区分 section 粒度。冲刺期套卷日 vs 复盘日的耗时差异会比较大，这个粒度后续可以优化。

## 二、v2 新增功能验证

### 2.1 跨科目 ROI 优先级排序（"今天先救谁"）

**v2 设计**：§11.2 第 3-4 步，ROI 打分 0-10，综合 4 因子：落后幅度（gap）、科目分值权重（数学 150 > 英语/政治 100）、补救边际收益（刚启动/掌握率低的边际收益高）、距 deadline 紧迫度。输出 P0/P1/P2。

**验证结论：⚠️ 部分解决**

- ✅ 排序思路正确：综合了 v1 用户一、用户三、用户五共同要求的"分值权重 + 边际收益 + 落后幅度 + 紧迫度"四因子。
- ✅ 输出 P0/P1/P2 分级，不再并列红牌。
- ❌ **缺具体算法公式**：四个因子各自占多少权重？怎么合成 0-10 分？是加权求和还是取最大值？PRD 没说。实现时开发同学可能自己拍一个，导致排序结果不可预测。
- ❌ **"边际收益"的量化方式未定义**：什么叫"刚启动边际收益高"？高多少？是线性递减还是对数曲线？没有函数形式。

**补充建议**：补一段 ROI 计算公式示例，例如：
```
ROI_score = w1 * gap_normalized + w2 * subjectWeight + w3 * marginalBenefit + w4 * urgency
默认权重：w1=0.35, w2=0.25, w3=0.25, w4=0.15
（用户可在设置里调权重，比如不考数学的人把 w2 数学权重降为 0）
```

### 2.2 偏科补救分阶段计划（§11.8）

**v2 设计**：
- 4-8 周分阶段时间表，落 `ai_plan_records(kind=remediation)`
- 每周一调各科日量、每周日复盘进度动态修正
- 附可持续性预览："按此节奏数学 4 周追到 70%，但专业课可能从正常滑到落后 10%，接受吗？"
- 超前科目不只降速，还检查其薄弱子模块做"科目内再平衡"
- action：`start_remediation_plan`（可 abort）

**验证结论：✅ 已解决（结构完整，爬坡曲线待细化）**

- ✅ v1 用户五的核心诉求——"分阶段补救时间表 + 每周复盘 + 可持续性预览"——全部落地。
- ✅ "超前科目降速 + 科目内再平衡"回应了用户五"超前科目不该只降速，还该挖薄弱子模块"的建议。
- ✅ 有数据模型（`ai_plan_records`）、有 action（`start_remediation_plan`）、有接口（`POST /api/ai/plan/remediation`），可操作性强。

**遗留缺口**：
- 分阶段的"爬坡曲线"没说——第 1 周加多少、第 4 周降到多少，是线性爬坡还是前快后慢？PRD 只说"4-8 周分阶段"，没给默认节奏模板。实现时可能需要 AI 每次现场生成，导致不同用户拿到的方案差异大。建议补一个默认爬坡模板（如：补救科前 2 周加 30%、第 3-4 周加 50%、第 5 周起逐步回落到正常）。

### 2.3 周计划补位

**v2 设计**：
- F5.5 周计划生成【新】：每周日晚自动出下周各科目标，一键写入 dailyCapacity
- action：`generate_weekly_plan`
- 接口：`POST /api/ai/plan/weekly`
- 落 `ai_plan_records(kind=weekly)`

**验证结论：✅ 已解决**

- v1 用户三明确提出"强化期周计划缺失，只有今日计划和冲刺日计划"——v2 补上了 F5.5，且有完整的数据模型、action、接口。
- "一键写入 dailyCapacity"让周计划不只是看看，而是能落地到每日排期。
- 优先级标为 P1（在 M3 上线），符合其重要度。

### 2.4 冲刺减法清单

**v2 设计**：
- §11.3：每天筛出"已掌握且连续 3 次记得"的条目，自动 `lower_mastered_freq` 降为低频
- 明确告诉用户"这些今天可以不做"
- action：`lower_mastered_freq`（逆操作：恢复每日）
- 节奏型排期：数学"一三五套卷/二四六复盘/周日模考"，政治"每天 2 大题+50 选择"，专业课"每天回顾 1 章+周末默写"
- 背书停新 ≠ 刷题停新（冲刺期刷题反而要加新模拟卷）

**验证结论：✅ 已解决（规则具体，"低频"频率待明确）**

- ✅ v1 用户四"冲刺期需要减法清单"的诉求完全回应：有筛选规则（已掌握+连续 3 次记得）、有 action（`lower_mastered_freq`）、有话术（"这些今天可以不做"）。
- ✅ 节奏型排期回应了用户四"套卷日 vs 复盘日节奏编排"的建议。
- ✅ "背书停新≠刷题停新"是 v2 的亮点设计，避免了一刀切停新。

**遗留缺口**：
- "降为低频"的具体频率没说——是每 2 天过一次？每 3 天？每周？v1 用户四建议"每 3 天过一次"，v2 没采纳这个具体数字。实现时需要定义默认低频间隔。建议明确：冲刺期已掌握条目降为每 3 天过一次（即原间隔 ×3）。

## 五、总体结论

### v2 的全局调度能力是否达到了可用水平？

**结论：✅ 达到了可用水平，核心闭环完整。**

v2 对混合场景的改进是**架构级重写**而非打补丁：

1. **输入闭环**：用户输入今日时间预算（F1.7 chips）→ AI 在硬约束下调度 → 输出带分钟数的 P0/P1/P2 时间块 → 一键应用（有升有降的 adjust_daily_capacity）→ 可撤销。这个闭环是完整的，用户从"打开 AI 问今天干嘛"到"落地到系统日量"全程不用手动算。

2. **数据闭环**：subjectKey 打通同科目三项目 → minutesPerUnit 统一单位 → 热力图输出科目级薄弱视图 → 跨项目 action（add_mistake_from_exercise）打通刷题→错题通道。数据不再是孤岛。

3. **规划闭环**：今日计划（§11.2）→ 周计划（F5.5）→ 偏科补救分阶段计划（§11.8）→ 冲刺减法清单（§11.3），四个时间粒度都有覆盖，不再只有"今天做什么"和"冲刺做什么"两个极端。

### 从"可用"到"好用"还差什么？（按优先级）

1. **【P0】补 ROI 打分的显式权重公式**——否则排序结果不可预测，用户无法信任"今天先救谁"的结论。
2. **【P1】明确"低频"的具体频率**（建议：冲刺期已掌握条目降为每 3 天过一次）。
3. **【P1】补偏科补救的默认爬坡曲线模板**（前几周加多少、什么时候回落）。
4. **【P2】SRS 排期真正合并**：同一知识点 tag 的背书条目和错题条目自动排到同一天，而不只是"提示一起复习"。
5. **【P2】时钟时间轴**：结合 peakTime 画像，把时间块排到具体钟点（9:00-11:30 数学…），降低用户的排期认知负荷。
