## 一、错题本模块验证

### 痛点 1：聚类算法绑死数学章节树+页码，英语/政治/文科失灵

**v1 痛点描述：** §11.1 聚类完全建立在"units 章节树 + 页码"映射上，英语阅读按题型组织、政治按考点号组织、文科专业课无页码，导致 F3.2/F3.3 对这三类用户基本失效。这是错题诊断模块最结构性的短板。

**v2 对应设计：**
- §11.1 算法第 1 步明确为**三维聚类，归类口径三选一**：
  - 章节口径：页码/题号段 → units 叶子章（数学/专业课）；
  - **题型口径**：`questionType`（细节/推断/主旨…）× 错法二维矩阵（英语）；
  - **语义口径**：content/note 关键词轻量聚类，同考点换皮题合并成"考点簇"（文科/跨章节重复考点）。
- §5.3 store 新增错题 item 字段：`questionType`（题型，非页码聚类用）、`examYear`（考期/年份）。
- §7.2 聚合器第 1 条：无 units 页码时自动降级——"有 units 页码→章节树口径；无页码但有 questionType→题型×错法矩阵；都没有→按 content/note 关键词轻量聚类"。
- F3.2 描述："三维聚类：章节树 / 题型考点标签 / 语义关键词；无页码项目也能用"。
- §7.2 同时规定 **note 抽样回注**：只对 `errTag∈{概念不清,思路错误}` 且 note 长的条目读 note（≤20 条），平衡 token 与信息丰富度。

**验证结论：✅ 已解决**

v2 从"单维页码聚类"升级为"三维自动降级聚类"，数学走章节树、英语走题型矩阵、文科走语义关键词，三个口径互斥且自动选择，直接回应了 v1 评审中用户 2（英语）、用户 3（政治）、用户 4（文科）、用户 4 专业课（跨章节重复考点）的结构性投诉。`questionType` 字段的补入让英语"题型×错法矩阵"有了结构化数据入口。note 抽样回注（≤20 条）也解决了 v1 用户 10 提出的"长 note 被一刀切砍掉"问题。

**补充建议（非阻塞）：** 语义聚类目前描述为"轻量聚类"，未明确相似度算法（TF-IDF？embedding？）。建议在实施时明确：本地优先用关键词共现 + 编辑距离做轻量聚类，若效果不佳再考虑引入本地小模型 embedding。这属于实现细节，不影响设计验收。

### 痛点 2：只诊断错在哪，缺"今天有限时间先做哪 3 道"的落地切片

**v1 痛点描述：** §11.1 输出停在"先二刷某章"一句话，`create_review_list` 只建清单，没有"今天先用 30 分钟做这 3 道"的取舍式切片。用户 1（200+ 道焦虑爆炸）、用户 9（在职只有 2 小时）、用户 6（不复习启动难）均要求"最小下一步 + 时间约束"。

**v2 对应设计：**
- F3.5【新】**时间预算切片**：用户给"今天 X 分钟"，切出 3–5 道最高 ROI，其余折叠"暂存"。
- F1.7【新】**今日时间快捷输入**：输入框旁"⏱ 今天可学 __h" chips（1h/2h/4h/全天），规划类意图必带。
- §8 Prompt 工程："错题诊断 prompt 强制末尾带'最小下一步 + 预计分钟'"。
- §11.1 输出示例完整落地：
  ```
  你数学 200+ 道错题，今天只给了自己 2 小时 →
  【今天只做这 4 道】约 50 分钟：中值定理 wrongStreak 最高的 4 道（其余 196 道已折叠，别碰）
  ```
- F3.3 升级：`create_review_list` 标签上直接显示"共 N 条·约每日 X 分钟"。
- §7.2 第 3 条：所有"建议日量"统一乘 `minutesPerUnit` 得分钟，action 标签显示"约 X 分钟"。
- §11.2 全局时间守恒调度（P0）在更高维度上解决此问题：用户输入 budgetMin 后，AI 在硬约束下做此消彼长分配，输出 P0/P1/P2。

**验证结论：✅ 已解决**

v2 从三个层面闭环了这个痛点：①输入层 F1.7 时间 chips 让用户一键给出预算；②算法层 F3.5 按预算切 3–5 道最高 ROI、其余折叠；③输出层 §11.1 示例和 §8 prompt 强制要求"最小下一步+预计分钟"。`minutesPerUnit` 推断让"约 X 分钟"有数据支撑而非拍脑袋。"错题洪水开关"（用户 1 建议）以"其余折叠为暂存"的形式落地。

### 痛点 3：默认用户会维护 errTag/mastered，但实际伪掌握/只记不练

**v1 痛点描述：** PRD 假设用户认真打 errTag、诚实标 mastered、会主动复习。但真实重度用户要么不打标签、要么标错（伪掌握 manualMastered=true 但 reviews 仍忘）、要么只记不复习、要么过度整理代替重做。v1 缺少自动补全与行为纠偏。

**v2 对应设计：**
- F3.6【新】**行为诊断**：伪掌握/跨年顽固/只记不练/过度整理，纯本地戳破。
- §7.2 第 4 条明确定义四类行为诊断算法（纯本地零 token）：
  - **伪掌握**：`manualMastered=true` 且后续 reviews 仍出现 result=忘记；
  - **跨年顽固**：`learnedDate` 跨年且同簇仍在错；
  - **只记不练**：mistake 项目 records/items 增长但 reviews=0 持续 N 天；
  - **过度整理**：note 长度分位很高但二刷正确率低。
- §6.2 新增接口 `GET /api/ai/behavior-diag`：输出四类行为诊断结果（纯本地）。
- F3.8【新】**自动补标签**：无 errTag 时 AI 按内容建议标签/自动归类（回应 v1 用户 9"在职没时间标标签"）。
- §11.1 输出示例含"戳破一个假象：你标了 mastered 的 3 条，近 3 次复习其实忘了 2 次（伪掌握）"。
- §11.1 附带 actions：伪掌握条目回流 `add_recite_items`（回应 v1 用户 4"错题→记忆条目转化"建议）。

**验证结论：✅ 已解决**

v2 不仅覆盖了 v1 评审点名的三类行为（伪掌握、跨年顽固、只记不练），还额外补了"过度整理"（用户 10 完美主义型痛点）。四类诊断全部纯本地零 token，符合省钱原则。F3.8 自动补标签解决了"用户不打 errTag 导致诊断输入质量崩塌"的问题。伪掌握条目回流 SRS 的 action 闭环了"错题→记忆"的转化路径。

## 二、刷题本模块验证

### 痛点 1：套卷数据建模薄，缺 score/timeSpentMin

**v1 痛点描述：** 套卷 records 只有 `date, startPage, endPage`，没有 `score` 或 `timeSpentMin` 字段。`paperSections` 只有 `weight`（权重）没有实际得分和逐 section 用时。AI 想分析"阅读正确率趋势""作文用时是否恶化"连原始数据都读不到。

**v2 对应设计：**
- §0 系统事实第 2 条：套卷 `records[]` 增加 `score`（总分）、`sections:[{name, score, fullScore, timeSpentMin}]`（逐 section 得分与用时）。
- §5.3 store 新增字段确认：套卷 record：`score`(float)、`sections:[{name,score,fullScore,timeSpentMin}]`。
- §6.2 新增接口 `GET /api/ai/paper-trend?projectId=`：返回逐套 `{seq, date, score, sections:[{name, score, timeMin}]}`，供趋势解读。
- F7.3【新】**套卷趋势解读**：逐套总分/section 得分/用时趋势。
- v2 修订说明 B.1："补套卷数据模型：套卷 records 增加 score 与按 section 的 {score, fullScore, timeSpentMin}；新增 /api/ai/paper-trend 本地趋势接口。"

**验证结论：✅ 已解决**

v2 在数据模型层（§5.3）、接口层（§6.2 paper-trend）、功能层（F7.3）三层闭环补全了套卷建模。`sections` 数组同时记录 `score`（得分）和 `timeSpentMin`（用时），直接回应了 v1 用户 2（英语真题正确率趋势）、用户 5（套卷模拟型时间分配诊断）、用户 9（真题迷茫型）的核心诉求。paper-trend 接口走 L0 本地聚合，不花 token。

---

### 痛点 2：actions 白名单只会调日量，缺砍范围/建套卷/方案对比

**v1 痛点描述：** v1 §9.1 actions 白名单只有 `adjust_daily_capacity`（调日量）、`adjust_deadline`、`create_project`、`add_recite_items`、`create_review_list`、`adjust_intervals` 六个 op。AI 落后时只会"加日量"，不能帮用户砍范围（标记章节选做）、不能基于外部资料建空套卷项目、不能给多方案让用户选。

**v2 对应设计：**
- §9.1 动作白名单从 6 个扩到 **15 个**，新增三个直接回应本痛点：
  - **`mark_units_optional`【新】**：把某些章节/范围标记为选做/砍范围（砍范围而非加日量），逆操作为"恢复为必做"；
  - **`create_mock_paper_project`【新】**：基于外部资料名（如李林6+4）建空套卷项目，用户后续录分，逆操作为"删该项目"；
  - **`compare_plans`【新】**：输出多方案对比卡（加日量/推期/砍范围三选一），用户勾选其一后才落地，本身不直接改数据。
- §11.6 阶段切换：store 外资料建议可附 `create_mock_paper_project` action；建项目前查重避免重复创建。
- §11.2 全局调度输出附带 `compare_plans`（若用户想换方案）。

**验证结论：✅ 已解决**

三个新 op 精准对应 v1 评审中用户 1（数学落后要砍范围）、用户 6（慢热型要取舍计划）、用户 10（冲刺型要 store 外资料建议）的诉求。`compare_plans` 的"先比后选"设计尤其好——它本身不改数据，渲染对比卡让用户勾，避免了 AI 替用户做决策。`mark_units_optional` 的逆操作（恢复为必做）保证了 op 级撤销闭环。

---

### 痛点 3：主动触达抓不到"刷得多不总结""稳定低产出""双项目并行"

**v1 痛点描述：** v1 §11.5 触发规则只有"连续≥3天无 records""gap<-0.3 严重落后""复习积压连续3天增长"三条。但用户 8（刷题不总结）每天 records 很多、gap 是正的，三条都不命中；用户 6（稳定低产出）天天打卡但日量很低，AI 只会反复标红"落后"；用户 9（双项目并行）章节+套卷都在刷但都不深入，没有触发规则覆盖。

**v2 对应设计：**
- §11.5 主动触达在 v1 基础上**新增三条触发信号**：
  1. **错题本连续 7 天无 review**（只刷新题不总结型）；
  2. **稳定低产出**：连续 14 天每日产出低于阈值但天天打卡（不催加速，而是"按你实际节奏重排/砍范围"）；
  3. **双刷题项目并行且任一完成率 <80%**（章节+套卷都在刷但都不深入 → 给并行过渡方案）；
  4. 待复习逾期数 > 阈值（针对"打卡了但清不完积压"）。
- 话术原则沿用 v1：不说鸡汤，给"最小第一步 + 预计分钟"。
- F6.1 升级描述："触发规则扩到隐性问题（见 §11.5）"。

**验证结论：✅ 已解决**

三条新触发规则与 v1 评审汇总中列出的 Top 3 改进建议第 3 条一一对应：
- "错题本连续7天无review" → 用户 8（刷题不总结型）；
- "稳定低产出连续14天" → 用户 6（慢热型）；
- "双刷题项目并行且任一完成率<80%" → 用户 9（真题迷茫型）。
特别值得肯定的是"稳定低产出"的话术方向——"不催加速，而是按你实际节奏重排/砍范围"，这直接回应了用户 6 提出的"AI 只会告诉我你落后了，这对我是二次伤害"。

## 三、背书本模块验证

### 痛点 1：自问自答形态一刀切，不贴合大题/作文/名词/公式

**v1 痛点描述：** §11.4 只做"出 3 个问题→看答案要点"一种形态。但政治大题要分采分点串段、英语作文要换题仿写批改、名词解释要挖空、数学公式要双向卡+陷阱题、论述题要关键词骨架扩写——一刀切的问答模型对后四类几乎错位。

**v2 对应设计：**
- §11.4 **按 `item.form` 自适应出题**，定义了 5 种形态：
  | form | 出题形态 |
  |---|---|
  | `term`（名词解释） | 挖空自测：把答案关键词挖掉让填 |
  | `essay`（政治大题/论述） | 自动切采分点，抽点默背→串段成300字，点模糊勾"忘了原理段还是材料段" |
  | `composition`（英语作文） | 出新题让用户套模板仿写，AI 逐句对照原文批改 |
  | `formula`（公式） | 双向卡（给公式默写条件 / 给场景选公式）+ 适用条件陷阱判断题 |
  | `discuss`（简答论述） | 抽关键词骨架→让用户扩写成段→对照原文 |
- F4.2【升】**按形态自适应出题**：挖空/采分点抽问/仿写批改/双向陷阱卡。
- §5.3 背书 item 新增字段：`form`（`essay|composition|term|formula|discuss|qa`）、`points[]`（采分点骨架）。
- §8 Prompt 工程："出题类按 item.form 走不同子模板（§11.4）"。

**验证结论：✅ 已解决**

v2 的形态自适应设计与 v1 评审中 5 类用户的诉求一一对应：
- 政治大题（用户 1）→ essay 采分点抽问+串段；
- 英语作文（用户 2）→ composition 换题仿写+逐句批改；
- 名词解释（用户 3）→ term 挖空自测；
- 数学公式（用户 4）→ formula 双向卡+适用条件陷阱题；
- 简答论述（用户 10）→ discuss 关键词骨架扩写。
`points[]` 采分点骨架字段的补入，让 essay/discuss 形态有了结构化数据支撑，不再依赖 AI 自由发挥。

---

### 痛点 2：主动回忆藏在手动点击里，不是默认流程

**v1 痛点描述：** F4.2 是"我主动在某条 item 上点让 AI 考我"——但死记硬背型用户（用户 6）恰恰不会去点。【记得/模糊/忘记】三态粒度太粗，无法记录"哪一段忘了"，也无法防止"假记住"自欺。

**v2 对应设计：**
- F4.5【新】**默认遮罩回忆**：打开复习即遮罩答案先回忆；点记得前强制默写关键词；点模糊勾选遗忘点。
- §11.4 默认交互升级明确写明：
  > 打开背书复习列表**即遮罩答案**，先回忆再核对（不再是藏在菜单里的按钮）；点"记得"前强制在输入框敲 1–2 个关键词防自欺；点"模糊"可勾选"忘了哪个点"，SRS 只对该点缩短间隔。
- 这同时解决了三个子问题：
  1. **从可选变默认**：打开复习列表即遮罩，不需要用户主动点按钮；
  2. **防自欺**：点"记得"前强制默写 1–2 个关键词；
  3. **按点反馈**：点"模糊"可勾选"忘了哪个点"，SRS 只对该点缩短间隔，而非整条退回重学。

**验证结论：✅ 已解决**

v2 把主动回忆从"藏在菜单里的 AI 按钮"升级为"打开复习列表的默认遮罩流程"，直接回应了用户 6（死记硬背型）的核心痛点——"我这种人恰恰不会去点"。强制默写关键词防自欺（用户 6 痛点 2）和按点缩短间隔（用户 10 痛点 3）也一并落地。这是背书模块从"P1 可选功能"升级为"P0 默认流程"的关键转变。

### 痛点 3：积压/逾期只有话术，没有自动处理 action

**v1 痛点描述：** F4.1 只"报数解读"不"减负"。120 条到期时系统只告诉用户"这里面 20 条高危"，但没有 action 把低危条目顺延。§11.5 只干预断签不干预积压。逾期条目全标红，越攒越多越不敢打开。

**v2 对应设计：**
- §9.1 新增两个积压处理 op：
  - **`defer_low_risk_items`【新】**：顺延低风险到期条目 1–2 天（清积压），逆操作为"恢复到期日"；
  - **`compress_intervals`【新】**：考前临时把某项目 intervals 压成更密的短间隔，逆操作为"恢复原 intervals"。
- F4.6【新】**积压减负**：`defer_low_risk_items` 顺延低危、`compress_intervals` 考前压间隔。
- §11.4 积压减负段落：
  > 今日到期量 > 每日可复习上限时，`defer_low_risk_items` 把低危顺延 1–2 天、**逾期折叠不堆红**，首页只显示"今天先清这 8 条约 20 分钟"。
- F4.1 升级："不只报数，给'今天先清这 N 条高危约 X 分钟'，逾期折叠不堆红"。
- §11.5 新增触发第 4 条："待复习逾期数 > 阈值"（针对打卡了但清不完积压）。

**验证结论：✅ 已解决**

v2 从三个层面闭环了积压痛点：
1. **action 层**：`defer_low_risk_items` 真正能改数据（顺延到期日），不是只给话术；
2. **交互层**：逾期折叠不堆红，首页只显示"今天必做 N 条"最小路径；
3. **触达层**：§11.5 新增"待复习逾期数>阈值"触发，覆盖"打卡了但积压清不完"的用户。
`compress_intervals` 同时回应了用户 9（考前 SRS 弹性）的诉求。两个 op 都有逆操作，保证撤销闭环。

## 五、总体结论

### v2 是否可以进入实施阶段？

**结论：✅ 可以进入实施阶段。**

**理由：**

1. **9 项 Top 痛点全部得到结构性解决**，而非"加一句已考虑"。每个痛点都能在 v2 中找到对应的：
   - 具体章节设计（§11.1/§11.4/§11.5/§11.6）；
   - 数据字段（questionType/examYear/form/points[]/score/sections 等）；
   - API 接口（paper-trend/behavior-diag/today/subject-heatmap）；
   - action op（mark_units_optional/create_mock_paper_project/compare_plans/defer_low_risk_items/compress_intervals）。

2. **v2 修订说明（§A/§B/§C）与评审文档的 Top 3 建议高度对齐**，说明修订是有的放矢而非泛泛而谈。修订说明中列出的每条变更都能追溯到具体评审用户的诉求。

3. **路线图（§13）合理**：M1 做入口和算账、M2 做应用+全局调度+错题、M3 做背书+触达+热力+补救、M4 做冲刺长尾。P0 功能集中在 M1-M2，P1 功能在 M3-M4，优先级划分清晰。

4. **老用户零伤害**：所有新 store 字段均为可选、缺省补默认（§12），符合 v1 架构决策延续。
