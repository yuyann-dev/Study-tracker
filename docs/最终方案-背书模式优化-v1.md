# Study Tracker 背书模式（recite）排期优化 — 最终方案 v1

> 产出日期：2026-10-05
> 依据文档：《背书模式逻辑盘查.md》+ 8 份背书用户模拟 +《最终方案-错题本排期优化-v3.md》（借鉴模式，不改 mistake 代码）+《最终方案-刷题模式优化-v2.md》（借鉴模式）
> 代码基准：`frontend/js/app.js`（约 14900 行）、`frontend/index.html`、`frontend/css/style.css`
>
> **最高产品约束（编码时不得违背）：**
> 1. 后移截止日不是首选；`hardDeadline===true` 全程不见后移；后移仅作最后兜底且带"如果不是硬约束"。
> 2. 所有新 UI 都在背书本页面内，不碰 Dashboard/今日总览。
> 3. 提示可关闭但只当天有效（写 `xxxShownDate/DismissedDate = todayStr()`），无永久静音。
> 4. 舒适量建议不死锁：触发靠"连续轻松/吃力"行为信号；"最近 7 天实际日均"只作为文案参考与建议值贴近度，不直接把舒适量设成 EWMA、不自动改。
> 5. 舒适量下限：智能模式（avg）不低于 4（绝对底 3），固定模式（fixed）不卡下限——用户自己锁的日量。
> 6. 老用户兼容：新字段迁移层兜底，老数据不崩。
> 7. 不改 mistake / exercise 已优化代码（只调用 `scheduleNextReview`、`transitionReview` 等共享内核函数）。
> 8. 背书有自己的三态间隔重复内核（记得/模糊/忘记），方案必须尊重这个内核，不破坏。
> 9. 术语口径：背书统一用"掌握/条/背诵"，错题用"攻克/道/错题"；代码变量 `isMastered` 不变。

## 0. 一句话总览

背书（recite）复用了错题本的三态间隔重复内核（`transitionReview`/`applyReview`/`renderReview` 完全共用），但外围调度层是"半套"：录入不错峰（P1-01）、策略条死代码（P1-02）、舒适量/容量机制对新学不完整、过期横幅文案硬编码"错题本"。本方案围绕**十件事**：把每日目标拆成"复习+新学"双轨控制、补中性提示与智能建议、修活策略条（暂停新学/低频降频/冲刺可见）、修录入错峰、补进度透明与可行性判断、补过期/归档闭环、修文案出戏问题。

核心：**新增 `newLearnCap`（每日新学上限）+ `reciteMode`（smart/fixed）**，实际每日复习目标 = fixed 取 `dailyCapacity`、smart 取 `max(舒适量, getDailyCapacity)`（超舒适量时给中性提示）；新学目标 = `min(newLearnCap, newCap均摊)`。v1 在 M1/M2/M3/M6/M7/M8/M9/M10 补齐容量双轨、策略条活过来、录入错峰、进度透明、软鼓励与设置页。

## 3. 核心算法：背书每日目标（复习 + 新学双轨）

```js
// 取舒适复习量
function getReciteComfort(p) {
  let c = parseInt(p.spreadThreshold, 10);
  if (!isFinite(c) || c < 1) c = 6;
  c = Math.round(c);
  if (p.reciteMode === 'fixed') {
    return Math.max(1, c);                 // fixed：不卡下限，用户自定
  }
  return Math.max(4, c);                   // smart：下限 4（绝对底 3）
}

// 每日复习目标（due items 侧）
function getReciteReviewTarget(p, date) {
  const comfort = getReciteComfort(p);
  if (p.reciteMode === 'fixed' && p.dailyCapacity != null) {
    return Math.max(1, Math.round(p.dailyCapacity));  // fixed：锁死容量，不受舒适量截断
  }
  // smart 模式
  const cap = getDailyCapacity(p, date);           // 现有函数，不改
  const today = todayStr();
  if (date === today) return Math.max(comfort, cap);
  return Math.max(1, Math.min(50, cap));
}

// 每日新学目标（newCap 侧）
function getReciteNewLearnTarget(p) {
  if (p.pauseNewLearning) return 0;               // 暂停新学开关
  const newCap = getDeadlineLevelCap(p).newCap || 0;  // 现有函数，不改
  if (p.newLearnCap != null && isFinite(p.newLearnCap)) {
    return Math.max(0, Math.min(newCap, Math.round(p.newLearnCap)));
  }
  return newCap;                                   // null = 自动均摊
}
```

**关键设计决策：**
- **fixed 模式解耦舒适量**：固定复习日量 = `dailyCapacity` 本身，不再 `min(舒适量, dailyCapacity)`。这修复了"设 30 被舒适量 6 截断成 6"的痛点（固定容量高用户）。
- **smart 模式舒适量是地板不是天花板**：复习目标 = `max(舒适量, smartCap)`，超舒适量时给中性提示（M2），不硬卡。
- **新学独立控制**：`newLearnCap` 让用户能单独压新学速率，不被 deadline 反推的 newCap 绑架。
- **暂停新学**：`pauseNewLearning=true` 时 newCap=0，录入区收起。

## 4. 逐模块详细设计（触发条件 / UI 位置 / 文案 / 按钮行为 / 边界）

> 所有 UI 都在背书本页面内（约束 2）。

### M1　舒适量 / 容量 / 新学上限设置

- **触发条件**：设置页对 recite 开放。新建 `reciteMode='smart', newLearnCap=null`。
- **UI 位置**：设置页"📈 每日节奏"区块（目标日下方）。包含：
  - 单选 `○ 智能节奏` / `○ 固定复习容量`
  - 智能模式显示：`每天舒适复习 ___ 条`（默认 6，下限 4）
  - 固定模式显示：`每天固定复习 ___ 条`（不卡下限）
  - 独立滑块：`每天新学上限 ___ 条（留空=自动按考试日均摊）`
- **校验**：
  - smart 模式：解析后 `<4` → 自动抬到 4，toast `智能模式下每日舒适复习量最低为 4 条，已按 4 保存`（绝对底 3：极端脏值不低于 3）。
  - fixed 模式：**不校验下限**。允许填 5、3、1；仅把 ≤0/NaN 兜底为 1。
  - newLearnCap：填 0 允许（等于手动暂停新学），留空 = null（自动）。
- **区块灰字说明**：
  > "智能节奏：按考试日自动均摊复习量，每天不低于你的舒适量；超过舒适量时会温和提示。固定复习容量：每天就做你设的这个量，做完即完成。新学上限：控制每天新背多少条，留空则系统按考试日自动算。"
- **配置矛盾提示（修复固定容量高用户痛点）**：
  - 触发条件：`reciteMode==='fixed'` 且 `dailyCapacity > getReciteComfort(p)` 且 `configWarnDismissedDate !== today`。
  - 文案：`⚖️ 你设了每天固定复习 {cap} 条，当前舒适量参考是 {comfort} 条。固定模式下按 {cap} 条执行，不受舒适量限制。`
  - 按钮：`[知道了]` → `configWarnDismissedDate = today`（当天有效）。
  - **v1 不做"一键改舒适量"按钮**（因为 fixed 模式已经不被舒适量截断了，矛盾自然消解）。
- **边界**：fixed 锁 30、smart 舒适量才 6 → 不报错，目标卡下方给小字参考（M8）。

### M2　超量中性提示（"系统计划 X，你的舒适量是 Y"）

- **触发条件**：全部满足——
  1. `p.type==='recite'`，`!p.archived`；
  2. `p.reciteMode==='smart'`；
  3. 当日复习目标 `getReciteReviewTarget(p, today) > getReciteComfort(p) × 1.3`；
  4. `p.comfortHintShownDate !== todayStr()`（每天最多 1 次）；
  5. M6 临考策略条不显示时才显示（互斥）。
- **UI 位置**：复习列表顶部，琥珀色中性小条（复用 `.neutral-banner` 样式）。
- **文案**：
  > "📚 今天系统计划复习 {target} 条，你的舒适量是 {comfort} 条。多出的部分主要来自 {source}（积压追赶/考试日均摊/星期画像）。先按舒适量做，剩下的系统会帮你往后挪。"
  - `source` 来源拆解：复用 `getSmartCapSource` 思路（但背书独立算，不调 mistake 的）。
- **按钮行为**：`✕` → `p.comfortHintShownDate = todayStr(); saveStore(); render();`（当天有效）。
- **hardDeadline 也显示但不提后移**。
- **边界**：fixed 模式不触发（用户自己锁的量，不需要提示）。

### M3　舒适量智能建议（调高 / 调低）

- **统计口径**：新增 `getReciteStreak(p)`，只看 items 里 reviews 记录的学习日完成量 vs comfort，**不读 EWMA 作为触发**。
- **三条建议（互斥，每天最多弹 1 条）**：
  1. **调高建议（smart/fixed 通用）**：连续 ≥7 学习日 `完成复习数 ≥ comfort × 1.3` + 距 deadline>14 天 + 当天未弹。
     - 文案：
       > "💡 你已连续 7 天轻松完成 {comfort} 条复习，最近 7 天实际日均约 **{avg7}** 条，状态不错。要不要把每日舒适复习量调到 **{suggestUp}** 条试试？（可随时调回）"
     - `avg7` = 最近 7 个学习日的平均完成复习数（**仅作文案参考**）；`suggestUp = Math.min(50, Math.max(comfort+2, Math.round(avg7)))`。
  2. **fixed 模式：不主动建议调低**。用户自己锁的硬日量，系统不劝降。
  3. **smart 模式调低建议**：连续 ≥21 学习日 `完成复习数 < comfort × 0.7` + backlog 稳定或下降 + 距 deadline>30 天 + `hardDeadline!==true` + 当天未弹。
     - 文案：
       > "💡 你最近的实际节奏约 {avg7} 条/天，低于舒适量 {comfort} 条。要不要把舒适量调到 **{suggestDown}**？状态好再往上加。"
     - `suggestDown = Math.max(4, Math.round(avg7))`（不低于下限 4）。
     - **`hardDeadline===true` 时整条不显示**。
- **按钮行为**：`[好，调到 N]` → `p.spreadThreshold=N`（smart 模式仍夹到下限 4）；`[不用]` → 当天关闭。
- **边界**：建议调高封顶 50；不自动改任何值；不直接用 EWMA 设舒适量。

### M4　过期处理（放开文案按类型区分 + hardDeadline 归档优先）

- **触发条件**：`p.deadline < todayStr()`、`!p.archived`、有未掌握条目。
- **UI 位置**：复用 `#deadlinePassedBanner`（app.js:6523），背书已显示（type!=='exercise'），**只需修文案**。
- **文案修复（P2-01）**：
  - `app.js:6563` "这本错题本陪你走过了备考的日子" → 按类型分支：
    - recite: `这本背书本陪你走过了备考的日子`
    - mistake: 保持原文
  - `app.js:6968` "错题会越攒越多" → recite: `待复习条目会越攒越多`
  - `app.js:6990-6992` honestHint 三元两支文案完全相同 → 合并为一条，按类型区分用词。
- **横幅按钮**：
  - **普通过期（hardDeadline=false 或未标记）**：
    - 刚过期（首次打开后≤3天）：`📌 目标日刚过去，还有 **{N}** 条未掌握` + 按钮：`[重设目标日]` `[一键重排旧题]` `[继续不赶进度]` `[归档这本]`
    - 过期较久（>3天）：`📌 目标日已于 {date} 到期，还有 **{N}** 条` + 按钮：`[重设目标日]` `[继续不赶进度]` `[归档这本]`
  - **hardDeadline=true 且已过期（考试日截止用户）**：
    - 文案：`📚 考试已经结束了。这本背书本陪你走过了备考的日子。`
    - 按钮：**`[归档这本]`**（主按钮，琥珀色实心）/ `[准备二战，重新设目标]` / `[以后再说]`
    - **完全不显示"重设目标日"作为主按钮**——对考试日用户，过期=战役结束。
- **"一键重排旧题"行为**：`rebalanceExpiredItems(p)`（已存在，type!=='exercise' 可用），把 nextReviewDate ≤ today 且 `canBeSpread=true` 的条目按正常间隔摊到未来。尊重防饥饿锁死规则。
- **"继续不赶进度"行为**：记录 `p.deadlineWarnDismissedDate = today`，同时触发 `rebalanceExpiredItems(p)`。之后每 7 天弹一次。
- **边界**：recite 过期后 `scheduleNextReview` 已不 clamp（条件 `deadline >= todayStr()`），新复习按自然间隔排未来——行为正确，不改。

### M5　归档功能

- **现状**：通用 `p.archived` + 过期横幅"归档这本"按钮对背书可用（P3 观察项）。收纳箱与"取消归档"已天然支持。
- **v1 补全**：
  - 背书本完成（所有条目 mastered/manualMastered）时，显示 `🎉 整本背完了 [归档这本]`。
  - 归档后保留所有数据，不删 items/reviews。
  - 收纳箱（项目列表底部"已归档"区）每个背书项目有"取消归档"按钮。
- **边界**：归档不影响 retention（保持期复习）的历史数据，只是从活跃列表隐藏。

### M6　临考策略条（修活 P1-02 + 暂停新学 + 低频降频 UI + 冲刺徽章）

这是本方案最核心的模块之一。

- **触发条件**：
  1. `!p.archived`、有未掌握条目；
  2. 距考试 `0 <= d2d <= 59`（进入冲刺窗口）；
  3. 且满足以下任一：
     - `d2d <= 30`（临考期）
     - 或 `pauseNewLearning === true`（用户手动开启）
     - 或 `getReciteFeasibility(p).level !== 'ok'`（进度落后）
  4. `p.sprintBarDismissedDate !== today`。
- **UI 位置**：复习列表顶部，琥珀色策略条（复用 `.tight-strategy-bar` 样式，独立组件 `renderReciteSprintBar`）。
- **冲刺徽章（常驻，不占策略条位）**：
  - 进入 `d2d <= 59` 时，在状态卡旁显示小徽章 `⚡冲刺模式`。
  - 徽章下方灰字说明：`距考试还有 {d2d} 天，你的模糊/薄弱项将在 3 天内高频复现。`
  - 每天首次进入时弹一行说明（`sprintBadgeShownDate` 频控），之后徽章常驻不弹窗。
- **策略条内容**：
  ```

  时间紧，做减法比硬赶新内容更有效：

  [⏸ 暂停新学，只复习]   [📉 低频内容降频]   [✂️ 战略放弃部分页]   [✕]
  ```

- **clamp 说明文案（修复临考用户"看不懂 clamp"痛点）**：

- **边界**：
  - 策略条与整段不出现"后移/延期"按钮；
  - hardDeadline 照常显示策略条（策略条是做减法，不是劝后移）；
  - ✕ 只当天有效；
  - 暂停新学/低频降频/战略放弃均可随时撤销。

### M8　进度透明化（落后/领先量化 + 可行性红绿灯）

- **触发条件**：点进背书本，有 total>0。位置：目标卡下方一行灰字。
- **文案**：
  > "已背 **{learnedPages}** / 共 **{totalPages}** 页（{percent}%）"
  - **落后**：`· 落后约 **{behind}** 条（≈落后 **{behindDays}** 天）`
  - **领先**：`· 领先约 **{-behind}** 条（≈领先 **{-behindDays}** 天）`

- **可行性红绿灯（新增 `getReciteFeasibility`）**：
  ```js
  function getReciteFeasibility(p) {
    const intervals = getIntervals(p);
    const cycleDays = getReviewCycleDays(p);
    const d2d = diffDays(todayStr(), p.deadline);
    if (d2d <= 0) return { level: 'ok', reason: '已过期' };

    const newLearnEnd = addDays(p.deadline, -cycleDays);
    const daysLeftNew = diffDays(todayStr(), newLearnEnd);
    const unlearned = getUnlearnedCount(p);  // 未学条目数

    if (daysLeftNew <= 0) {
      // 新学窗口已过
      const overdue = getOverdueItems(p).length;
      if (overdue > getReciteComfort(p) * 3) return { level: 'risk', reason: 'newLearnEnd_passed_with_backlog' };
      return { level: 'ok', reason: 'newLearnEnd_passed' };
    }

    // 新学窗口内：按当前节奏能不能学完？
    const ewmRate = getEwmRate(p, today);  // 现有函数
    const neededPerDay = Math.ceil(unlearned / daysLeftNew);
    if (ewmRate > 0 && neededPerDay > ewmRate * 1.5) {
      return { level: 'risk', reason: 'new_learning_too_slow', neededPerDay, ewmRate };
    }
    if (ewmRate > 0 && neededPerDay > ewmRate * 1.2) {
      return { level: 'warn', reason: 'new_learning_tight', neededPerDay, ewmRate };
    }
    return { level: 'ok', reason: 'on_track' };
  }
  ```
- **红绿灯显示**：

  - 🔴 `risk`：琥珀色提示条（不是红色）`⚠️ 按当前节奏，新内容可能赶不及在考试前学完。可以：① 调高每日新学上限 ② 暂停新学、集中复习已学 ③ 战略放弃部分低频页段。`

- **今日必啃清单（临考期）**：
