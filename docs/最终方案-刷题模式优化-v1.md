# 刷题模式（exercise）优化 — 最终方案 v1

> 产出日期：2026-10-05
> 依据文档：《刷题模式逻辑盘查.md》+ 8 份刷题用户模拟（大量/少量/固定容量低/固定容量高/临考冲刺/进度落后/刷题错题混合/考试日截止）+《最终方案-错题本排期优化-v3.md》（仅借鉴模式，不改 mistake 代码）
> 代码基准：`frontend/js/app.js`（约 1.7 万行）、`frontend/index.html`、`frontend/css/style.css`
>
> **本方案的最高产品约束（逐条落实，编码时不得违背）：**
> 1. **后移截止日不是首选**。首选永远是"优化策略"（砍题保分 / 优先高频 / 减少新页）。对 `p.hardDeadline === true`（截止日=考试日）的用户，**全程不出现任何"后移/延期"按钮与文案**。后移只在 `hardDeadline !== true` 时、作为最后兜底出现，且文案必须带"如果你的截止日不是硬约束"。
> 2. **不在今日总览（Dashboard）加任何新功能**。所有新 UI 都落在"点进某个刷题本之后"的页面内。
> 3. **提示可关闭但只当天有效**。所有关闭按钮只写 `xxxDismissedDate = todayStr()`，不写永久 mute（过期横幅的 `deadlineMuted` 是 mistake 既有逻辑，exercise 不新增永久静音）。频率由系统自定（默认每类提示每天最多 1 次）。
> 4. **舒适量建议不死锁**。禁止用"日均完成量 EWMA"反推舒适量（v3 BUG-03 已踩过这个坑：舒适量→目标→完成量→舒适量形成闭环）。只允许用"连续轻松完成天数 / 连续吃力天数"这两个**与目标值无关的行为信号**来建议。
> 5. **舒适量下限 = 6**（刷题本单位：页/套）。任何调高/调低/默认/迁移结果都不得低于 6。
> 6. **老用户兼容**。可激活僵尸字段（`dailyCapacity` / `spreadThreshold`），但老数据加载后不能崩、不能突然改目标。所有新字段在迁移层给兜底默认值。
> 7. **不改 mistake 已优化代码**。可以读取错题本的项目结构、调用既有 `scheduleNextReview`、按既有 mistake item 形状 `push` 条目；但**不修改** mistake 专属函数（excessBanner/pullForward/retention/rebalanceExpiredItems/getMistakeDayPlan 等）的任何逻辑。
> 8. **exercise 无 due 队列**。不能把 mistake 的 excessBanner 三档 / pullForward / ensureOne / retention / getDeadlineLevelCap / backlogCatchUp 直接搬过来。凡涉及"今天该复习哪几条"的，本方案一律不做（见 scope 边界）。

## 0. 一句话总览

exercise 是"剩余量 ÷ 剩余学习日"的纯进度推进器（`p.items` 恒空，进度全在 `p.records[]`）。本方案**不**给它造一个 due 队列，而是围绕"把每日目标从失控的均摊数，收敛到用户能接受的节奏；把过期/临考/收尾的闭环补上；把刷题做错的题一键盘到关联错题本"四件事展开。

核心改动一句话：**新增 `每日舒适量 dailyComfort`（默认 6，下限 6）+ `节奏模式 exerciseMode`（均摊/固定容量），让"实际每日目标 = 固定模式下取舒适量、均摊模式下取 min(舒适量, 均摊量)"；再把过期横幅、归档、临考策略条、错题快录、进度透明、软鼓励、设置入口这七块补上。**

## 3. 核心算法：exercise 每日目标（替换 `getDailyTarget` 在 exercise 上的输出）

新增纯函数 `getExerciseDailyTarget(p, m)`，**只在 `p.type === 'exercise'` 时被 `renderDailyGoal` 调用**，不影响 mistake/recite。

```js
// 新增：exercise 舒适量（带 6 下限）
function getExerciseComfort(p) {
  let c = (typeof p.dailyComfort === 'number' && isFinite(p.dailyComfort)) ? p.dailyComfort : 6;
  return Math.max(6, Math.round(c));          // 约束5：下限6
}

// 新增：exercise 实际每日目标
// 返回 { per, mode, comfort, avgPer, capped, remaining }
function getExerciseDailyTarget(p, m) {
  const comfort = getExerciseComfort(p);
  const remaining = Math.max(0, m.remaining || 0);
  if (remaining <= 0) return { per: 0, mode: p.exerciseMode, comfort, avgPer: 0, capped:false, remaining:0 };

  // 原均摊口径（保留现有 getDailyTarget 的产出，作为"均摊量 avgPer"）
  const raw = getDailyTarget(p, m);            // 现有函数，不改
  const avgPer = (raw.per != null && raw.per > 0) ? raw.per
              : (isFinite(m.needPerDay) && m.needPerDay > 0) ? m.needPerDay : comfort;

  let per;
  if (p.exerciseMode === 'fixed') {
    per = comfort;                             // 固定容量模式：锁死舒适量
  } else {
    per = Math.min(comfort, avgPer);           // 均摊模式：min(舒适量, 均摊量) —— 封顶不追高
  }
  // 收尾：别让目标超过剩余
  per = Math.min(per, remaining);
  return {
    per: round1(per),
    mode: p.exerciseMode,
    comfort,
    avgPer: round1(avgPer),
    capped: (p.exerciseMode !== 'fixed') && (avgPer > comfort + 1e-9), // 是否被舒适量封顶
    remaining
  };
}
```

**两种模式怎么服务不同画像：**
- **均摊模式（avg，新建默认）**：`per = min(comfort, avgPer)`。均摊量一旦因落后爬到 12，显示的目标不会超过 comfort（默认 6）——直接解决少量刷题用户"目标越算越高到 12 页吓退我"的焦虑。舒适量是**天花板**，不是地板。
- **固定容量模式（fixed）**：`per = comfort`。用户锁死每天 5 页/30 页，做满即打勾；均摊量降级成一行小字参考（"照这速度预计 X 完成，比目标日早/晚 Y 天"）。服务固定容量低/高两类用户。

**收尾边界**：`per = min(per, remaining)`。剩余只剩 3 页时目标就是 3，不再显示 6。

## 4. 逐模块详细设计（触发条件 / UI 位置 / 文案 / 按钮行为 / 边界）

> 所有 UI 都在"点进某个刷题本之后"的页面内（约束2）。按钮文案以"页/套"为单位，下面统一用"页"描述，套卷模式把"页"读作"套"。

### M1　舒适量 / 容量设置

- **触发条件**：设置页对 exercise 开放（见 M10）。新建时 `dailyComfort=6, exerciseMode='avg'`。
- **UI 位置**：刷题本设置页新增"📈 每日节奏"区块（放在目标日区块下方）。
  - 输入框：`每天舒适做 ___ 页`（min=6）。
  - 单选：`○ 均摊模式（系统按目标日算，不超过我的舒适量）` / `○ 固定容量模式（每天就做我设的这个量）`。
- **具体文案（区块说明灰字）**：
  > "均摊模式：系统按剩余页数÷剩余天数给建议，但每天不会超过你设的舒适量。固定容量模式：每天就做这个量，做完即打勾。"
- **按钮行为**：
  - 保存写 `p.dailyComfort`（`Math.max(6, parseInt)`，空则回退 6）、`p.exerciseMode`。
  - 保存后 `render()`，大数字立即按 §3 公式重算。
- **边界**：
  - 输入 < 6 → 强制抬到 6 并 toast 提示"刷题本每日舒适量最低为 6 页，已按 6 保存"。
  - `exerciseMode='fixed'` 且 comfort 远大于均摊量（如锁 30、均摊才 5）→ 不报错，在目标卡下方给小字参考（见 M8）。
  - 老 exercise（迁移后 dailyComfort=6）第一次进设置看到的就是 6，不突兀。

### M2　超量 / 落后中性提示（"系统计划 X，你的舒适量是 Y"）

- **触发条件**：全部满足才显示——
  1. `p.type==='exercise'`，`!p.archived`；
  2. `p.exerciseMode==='avg'` 且 `getExerciseDailyTarget(...).capped === true`（即均摊量 avgPer > comfort，被舒适量封顶了）；
  3. `m.remaining > 0`、`m.daysLeft > 0`（未过期；过期走 M4）；
  4. `p.comfortHintShownDate !== todayStr()`（每天最多 1 次）；
  5. 不是临考冲刺条已覆盖的同一场景（若 M6 正在显示，本提示让位，避免一屏两个盒子）。
- **UI 位置**：每日目标卡正下方、打卡区上方，一条**琥珀色中性条**（复用 `.ob-advice` / `.neutral-banner` 样式，**不用红色**）。
- **具体文案**：
  > "按目标日算，剩下的摊到每天约需 **{avgPer} 页**；你的舒适量是 **{comfort} 页**。今天先按 {comfort} 页推进就好，不必被那个大数吓到。"
  - 右下角一个 `✕`。
- **按钮行为**：点 `✕` → `p.comfortHintShownDate = todayStr(); saveStore(); render();`（只当天有效，明天再犯还会出现）。
- **边界**：
  - `fixed` 模式不显示（固定模式没有"均摊 vs 舒适量"的矛盾）。
  - `hardDeadline===true` 也显示，但文案**不出现任何"后移目标日"字样**（约束1），只陈述事实。
  - 用户当天已经做满 comfort 后，本条**自动隐藏**（已完成就不再施压）。

### M3　舒适量智能建议（不死锁、不低于 6）

- **触发条件**（两个独立方向，互斥）：
  - **建议调高**：`p.exerciseMode==='fixed'`（或 avg 但 comfort 明显偏低）+ 连续 **≥7 个学习日**当天完成量 ≥ `comfort × 1.3`（真轻松，不是压线）+ 距 deadline > 14 天 + `p.comfortAdviceShownDate !== today`。
  - **建议调低**：`p.exerciseMode==='fixed'` + 连续 **≥5 个学习日**当天完成量 < `comfort × 0.8`（真吃力）+ 距 deadline > 30 天 + `p.hardDeadline !== true` + 当天未弹。
  - **统计口径**：新增 `getExerciseStreak(p, m)`，只看 `p.records` 里"有完成量的学习日"是否连续达标，**绝不读 `perStudyDayRaw`/EWMA**（这是死锁红线，约束4）。
- **UI 位置**：与 M2 同区域（目标卡下方），同一条中性条风格，但语气是"建议"。
- **具体文案**：
  - 调高：`💡 你已连续 7 天轻松做完 {comfort} 页，状态不错。要不要把每日舒适量调到 {comfort+2} 页试试？（可随时调回）`
  - 调低：`💡 最近 5 天你都没做完 {comfort} 页，有点吃力。要不要把日量降到 {max(6,comfort-1)} 页，先稳住节奏？`
- **按钮行为**：
  - `[好，调到 N]` → `p.dailyComfort = N; saveStore(); render(); toast`。N 永远 `Math.max(6, ...)`。
  - `[不用]` → `p.comfortAdviceShownDate = todayStr();`（当天不再弹）。
- **边界**：
  - 调高建议值 `comfort+2`，**封顶建议到 30**（不鼓励无上限堆量）。
  - 调低不得低于 6；到 6 仍吃力 → 不再建议调低，转而提示"可以在临考策略条里砍题保分"（交给 M6）。
  - `hardDeadline===true` 时，调低建议仍可出现（它不碰 deadline），但不附带"后移目标日"。
  - 这是**建议**，用户点了才改；系统绝不自动改舒适量。

### M4　过期处理（放开过期横幅 + 状态卡不再画饼）

- **触发条件**：`p.deadline < todayStr()` 且 `!p.archived` 且 `m.remaining > 0`（没刷完）。
- **UI 位置**：复用既有 `#deadlinePassedBanner`（app.js:5827 `renderDeadlinePassedBanner`），放开它对 exercise 的隐藏。
- **改法（最小改动）**：
  - app.js:5830 现写 `if (!p || p.type === 'exercise') { banner.hidden = true; return; }`。改为：**不再对 exercise 早退**；把"liveCount"按类型取数——mistake 用 items，**exercise 用 `getMetrics(p).remaining`**（页/套剩余量）。
  - exercise 专属按钮（**去掉队列语义按钮**"一键重排旧题 / 继续不赶进度"，exercise 没有队列）：
    - 普通过期（`hardDeadline !== true`）：`[重设目标日]` `[归档这本]`。
    - **hardDeadline === true（考试日截止）**：文案改为 `📚 考试已经结束了。这本刷题本陪你走过了备考的日子。`，主按钮 = `[归档这本]`（琥珀色实心），次按钮 `[以后再说]`。**绝不出现"重设/后移目标日"作为引导**（约束1；"重设目标日"仅在普通过期出现）。
- **状态卡不再画饼**：`getStatusMessage` 分支5（app.js:4547）对 exercise 过期时，**不再渲染** `plan.onTime` / `plan.delay` 两块（过期时 `getCatchUpPlan` 本就返回空 plan，渲染它们等于画饼）。改成一句短文案：
  > "已经过了原定目标日 {deadline}，还剩 {remaining} {u}。之前刷的都还在——可以重设目标日接着推，或者把这本归档收起来。"
  （真正的按钮由上方过期横幅提供，状态卡只做陈述。）
- **按钮行为**：
  - `[重设目标日]` → `openSettings()`（定位到目标日输入框），沿用 mistake 既有 `data-dpa="reset"`。
  - `[归档这本]` → `p.archived = true; saveStore(); render(); toast('已归档，移到「已归档」收纳箱')`。
  - `[以后再说]` → `p.deadlineWarnDismissedDate = todayStr();`（当天有效）。
- **频率**：复用 mistake 既有频率控制（首次打开前 3 天每天弹，之后每 7 天一次），不新增永久 mute。
- **边界**：
  - `m.remaining === 0`（提前刷完但 deadline 没到）→ 不触发本横幅；走 M5 的"已完成"归档条。
  - exercise 过期**不调用** `rebalanceExpiredItems`（无 item，调用是空操作；不碰 mistake 代码）。

### M5　归档功能（exercise 可归档 + 收纳箱 + 取消归档）

- **现状**：`renderProjectList`（app.js:7580）已把 `p.archived` 项目收进"📦 已归档"收纳箱，且收纳箱对**所有类型**渲染、`data-unarchive` 事件（app.js:11868）已存在。也就是说**取消归档对 exercise 已经能用**——只差一个"把活动 exercise 变成 archived"的入口。
- **新增入口（两处，都在刷题本页面/既有生命周期控件内，不在 Dashboard）**：
  1. **已完成条**：`m.remaining === 0` 时，在目标卡下方显示一条完成条：`🎉 整本刷完了！` + `[归档这本]` 按钮。点 → `p.archived = true`。
  2. **过期横幅**：见 M4，`[归档这本]`。
  3. （可选增强）设置页底部"危险区"加一个小按钮 `归档这本`，对所有 exercise 可用。
- **UI 位置**：上述条内；收纳箱在项目列表底部（既有）。
- **按钮行为**：归档后 exercise 从首页"📚 刷题"分组消失，进入"📦 已归档"；点"取消归档"恢复。归档后不再出现在 Dashboard/提醒。
- **边界**：
  - 归档不删 `p.records`，打卡记录保留（满足"二战复盘/留痕"诉求）。
  - 关联错题本不受影响（`refProjectId` 还在）。
  - **不在 Dashboard/今日总览加归档控件**（约束2）。

### M6　临考策略条（距 deadline ≤30 天且落后）

- **触发条件**：全部满足——
  1. `p.type==='exercise'`，`!p.archived`，`m.remaining > 0`；
  2. `0 < m.daysLeft <= 30`；
  3. **进度落后**：`m.behind >= comfort`（落后量达到一天的舒适量，说明不是正常节奏）或 `m.feasibility === 'impossible'`；
  4. `p.sprintBarDismissedDate !== todayStr()`（每天最多1次）。
- **UI 位置**：刷题本页面顶部、目标卡上方，一条琥珀色策略条（复用 `.neutral-banner`，独立新组件 `renderExerciseSprintBar`，**不复用** mistake 的 `tightStrategyBar`，因为 exercise 无 due 队列——约束8）。
- **具体文案**：
  > "⏳ 距目标日只剩 {daysLeft} 天，还剩 {remaining} {u}（落后约 {behind} {u}）。时间紧，与其硬赶新页，不如做减法："
- **三个按钮**：
  1. **[暂停新页，优先复习]** → 切 `p.sprintPauseNewPages = true`。效果：当日目标卡改为"今日建议：停新页，去清关联错题本里的欠账"，并显示 `[打开关联错题本]` 快捷跳转（有 linked mistake 才显示）。再点一次可关（toggle）。
  2. **[砍题保分：标记低频章节放弃]** → 打开新面板 `openAbandonPanel(p)`：列出 units/章节（无 units 时按正文起止页分段），每行一个 `□ 标记为战略放弃`。勾选后写 `p.abandonedRanges` / `p.abandonedSets`。**`getMetrics` 算 total 时减去放弃部分**，并实时显示对比："放弃 {n} 页后，每天从 {oldPer} 降到 {newPer}，够得着了。"
  3. **[一键把今天的错题送进错题本]** → 有 linked mistake 则触发 M7 的错题录入弹层；没有则提示"先去创建关联错题本"。
- **按钮行为边界**：
  - **整条策略条不出现任何"后移/延期目标日"按钮**（约束1；砍题保分就是首选优化策略）。
  - `hardDeadline===true`：策略条照常显示（甚至更该显示），但文案强调"在现有时间内做取舍"。
  - `✕` 关闭 → `p.sprintBarDismissedDate = todayStr();`（当天有效）。
  - 砍题保分可撤销：`openAbandonPanel` 里取消勾选即从 `abandonedRanges` 移除，total 重算。
- **边界**：
  - 无 units 的纯页模式：放弃面板按"正文前/中/后三段"粗分，或允许手填放弃页码区间（复用 `readScopeRows` 的区间录入 UI）。
  - `abandonedRanges` 不计入 `total`，但 `p.records` 里已刷过的页不受影响（区间合并照常）。

### M7　错题联动（打卡时一键记错题 → 进关联错题本）

- **触发条件**：打卡成功（页模式 `btnCheckin` app.js:12212 / 套卷模式 `btnSetCheckin`）后，若该 exercise **已关联至少一个 page/set 模式 mistake 本**（`store.projects` 中 `type==='mistake' && refProjectId===p.id` 且模式匹配），弹出一个**轻量错题快录条**。
- **UI 位置**：打卡成功后，在打卡区下方就地展开一个小条（不跳页、不切项目）。
- **具体文案**：
  > "这 {startPage}–{endPage} 页里有做错的题吗？"
  > 输入占位：`如 45-12, 45-18（页-题号，题号先占位，题目回头补）`
  > `[记进关联错题本]` `[这次没有]`
- **按钮行为**：
  - 解析输入（逗号分隔），生成 `marks = ["45-12","45-18"]`。
  - **页模式**：每条 mark 形如 `{page, qno}`。在关联 mistake 本（page 模式）里 `push` 一个 item，形状**严格照抄既有 mistake item**（app.js:12344-12366）：
    ```js
    { id: genId(), content: `《${p.name}》p${page}-第${qno}题（待补题干）`,
      errTags: [], note: '打卡快录', learnedDate: date, stage: 0,
      nextReviewDate: null, reviews: [{date, quality:'fuzzy', stage:0}],
      mastered:false, manualMastered:false, wrongStreak:0, customIntervals:null,
      pageStart: page, pageEnd: page }
    ```
    然后**调用既有** `scheduleNextReview(linkedM, newItem, date, 0)` 排到未来（调用，不修改该函数——约束7）。
  - 同时把 marks 回写到这次打卡的 record：`r.wrongMarks = marks`。
  - 套卷模式：mark 形如 `{set, sec, qno}`，写 `newItem.setNo`，页面段对应 `paperSections`。
  - 无关联错题本时：按钮变成 `[去创建关联错题本]`，跳到既有 `openLinkedMistakes` 流程（已有，不改）。
- **边界**：
  - mark 解析容错：非法格式忽略；题号留空则只记到页（content = `《书名》p45 待整理`）。
  - 不自动推断错因/知识点（exercise 无题级数据，约束8）。
  - 这是"占位快录"，用户事后可进错题本补题干——把搬错题成本从 40 分钟压到 30 秒。
  - **不改 mistake 的任何既有函数**；只是按它的数据形状造 item + 调它的排期函数。

### M9　软鼓励（完不成目标时给低压力反馈）

## 7. Scope 边界（明确不做）

1. **不做 item 级间隔复习 / due 队列 / 二刷提醒**。大量刷题用户要的"7/15/30 天二刷队列"需要题级/页级时间戳排期，等于给 exercise 造半个 SRS——超出本方案，列入 v2 候选。本方案只做 record 上的 `wrongMarks` 标记。
2. **不做跨项目时间预算 / 新题+错题混合任务视图**。混合用户要的"今晚几页新题配几道错题"需要全局时间建模，不做。
3. **不自动推断章节重要性/高频低频**。砍题保分（M6）只接受用户手动标记，不接考纲/分值数据。
4. **不激活 classic/balanced 间隔模式、不读 intervals 表**。exercise 的间隔字段继续是僵尸数据（仅加代码注释说明）。
5. **不改任何 mistake 专属函数逻辑**（excessBanner/pullForward/retention/rebalance/getMistakeDayPlan 等）。
6. **不在 Dashboard/今日总览加新 UI**。
7. **不做永久静音**。所有关闭只当天有效。
8. **不把"后移截止日"作为首选**；hardDeadline 用户全程不见后移入口。
9. **舒适量建议不低于 6，且绝不以 EWMA/日均完成量反推舒适量**。
