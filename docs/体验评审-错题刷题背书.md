> 评审日期：2026-10-05
> 评审依据：PRD v2（`docs/AI助手产品需求文档-v2.md`）
> 审查代码：`frontend/js/app.js`（AIModule IIFE 15592–16408）、`frontend/index.html`（2176–2304）、`frontend/css/style.css`（2069–2328）、`backend/routes/ai.js`、`backend/utils/aiDataAggregator.js`

## 0. 先说全局结论（影响下面三类用户的共同前提）

在分角色之前，必须先点出一个**贯穿三类用户的致命链路 bug**，否则下面所有"建议卡片能不能用"的讨论都站不住：

### 🔴 阻断性 bug：「一键应用」必然失败，撤销永远不可用

- 后端 `POST /api/ai/chat` 的响应（`ai.js:501-508`）**只返回 `conversationId`，没有返回刚落库的 assistant 消息 `messageId`**（`saveMessage` 的 `lastInsertRowid` 在 `ai.js:497` 被丢弃）。
- 前端渲染建议卡时取 `resp.messageId || resp.id`（`app.js:16040`），结果永远是 `undefined` → 卡片记录里 `messageId = null`。
- 点击「应用选中」时，前端**先在本地改了 store 并 `saveStore()/render()`**（`app.js:15967-15972`），再带 `messageId: null` 调 `POST /api/ai/apply`（`app.js:15975`）。
- 后端 `/apply` 第一行就 `if (!messageId) return fail('缺少 messageId')`（`ai.js:563`）。

**用户实际看到的现象**：点「应用」→ 数据好像变了（本地确实改了）→ 立刻弹一个红 toast「⚠️ 应用失败：缺少 messageId」→ 卡片**不会**变成"已应用"态，**不会**出现撤销按钮；用户再点一次会**重复写入**（例如日量被连设两次、背书条目被重复 push）。

也就是说：PRD 最核心的价值主张「AI 说一句 → 一键改进系统 → 随时可撤销」（F10.1/F10.3）在当前代码下是**断的**。下面每类用户的"建议 action 是否能落地"，都受这个 bug 影响。

## 一、错题本用户视角

> 画像：强化期攒了 200+ 道错题，英语/政治错题没有章节树，希望 AI 帮他"今天只做最高 ROI 的几道、戳破假掌握、别让我对着 200 道发慌"。

### 1.1 已实现且好用的功能

- **mistake-report 接口存在且能跑通**（`ai.js:715` → `getMistakeReport`），能给出：errTag 分布、按章节聚类（`byUnit`）、按题型聚类（`byQuestionType`）、wrongStreak 高危榜（`streakyTop`）、伪掌握清单（`pseudoMastered`）、跨年顽固榜（`crossYear`）。
- **伪掌握检测逻辑方向正确**：`manualMastered=true` 且后续 reviews 出现 forget/忘记/模糊 即列入（`aiDataAggregator.js:301-305`）——这正是 PRD §11.1 要戳破的"假 mastery"。
- **跨年顽固检测**：`learnedDate` 年份早于今年且仍在错（`aiDataAggregator.js:307-312`），口径合理。
- **章节聚类做了页码→units 叶子章映射**（`aiDataAggregator.js:281-286`），数学这种有 units 的项目能按章聚合。
- **错误降级友好**：项目不是 mistake 类型或不存在时返回 `found:false + reason`，不会 500。

### 1.2 实现了但有问题的功能

1. **「三维聚类」严重名不副实——第三维"语义聚类"退化为 content 前 8 字分桶**
   - 代码：`semanticClusters[cut40(it.content).slice(0,8)]`（`aiDataAggregator.js:293-294`）。
   - 后果：「中值定理求导」和「中值定理应用」开头 8 字不同就分不到一簇；英语阅读、政治这种没有页码、靠考点归纳的错题，**真正需要的语义合并完全没发生**。PRD 要的"同考点换皮题合并成考点簇"（§11.1）没有实现。
2. **`create_review_list` action 根本不会改数据**
   - 前端 `SUPPORTED_OPS` 白名单（`app.js:15822`）里**没有 `create_review_list`**，`applyAction` 的 switch（`app.js:15897-15948`）也没有对应 case。
   - 后果：即便 AI 真的吐出"把中值定理这簇 4 道建成复习清单"这张卡，前端**不渲染勾选框**（`supported=false`），用户连点的地方都没有；PRD F3.3"一键建包、标签显示 N 条·约 X 分钟"完全落空。
3. **"没学过 vs 学了不会"交叉判断缺失**：PRD F3.4 要求交叉同章 exercise 进度、把未学完的章标灰提示"先补基础"。`getMistakeReport` 完全没读同科目 exercise 进度（`aiDataAggregator.js:240-338`）。
4. **时间预算切片（F3.5）没有入口**：`/mistake-report` 不接受 `budgetMin`，接口也不会"切出今天 3–5 道、其余折叠暂存"。错题洪水泄压的核心承诺没落地。
5. **跨年顽固的 `thisYear` 取当前年**（`aiDataAggregator.js:277`）：当前 2026-10，用户多数 learnedDate 是 2026，几乎不会触发"跨年"。逻辑没错，但对当前阶段用户等于空摆设。
6. **未锚定项目时拿不到报告**：`/mistake-report` 强制要 projectId（`ai.js:718`），用户若没在错题项目里打开 AI，就直接 fail，没有"自动识别你的错题项目"兜底。

### 1.3 PRD 有但未实现的功能

- **只记不练 / 过度整理两类行为诊断**（§11.1、§7.2.4）：代码只做了伪掌握 + 跨年顽固，"错题只增无 review""note 很长但二刷正确率低"两类完全没算。
- **粗标签二次细分**（F3.7）：粗心占比 >40% 时对 note 二次聚类（正负号/进位/漏条件）+ 流程矫正 action，未实现。
- **note 抽样回注**（§7.2.1）：对高价值 errTag 的长 note 抽样读入做错因归纳，未实现（现在 note 一律不进聚类）。
- **自动补标签**（F3.8）：无 errTag 时 AI 建议标签，未在聚合层体现。
- **对应 action 整体缺失**：`create_review_list`、流程矫正检查清单 action 均未接 store。

### 1.4 具体改进建议

1. **先修全局 messageId bug**（见第 0 节），否则错题建议卡永远"看着爽、点不动"。
2. **给 `SUPPORTED_OPS` 和 `applyAction` 补 `create_review_list`**：在错题项目里新建一个临时 mistake 子项目/标签，把选中簇的 item id 复制进去，label 带"N 条·约 X 分钟"。
3. **语义聚类换成真聚类**：至少按 errTag + 关键词去停用词后取 2–3 个关键词做 key（不要用 content 前 8 字）；英语/政治错题默认走这一维。
4. **`/mistake-report` 加 `budgetMin` 入参**，返回里把 streakyTop 切成"今天先做这 N 道"和"其余暂存"两段。
5. **补只记不练、过度整理两项本地诊断**，纯计数即可，零 token。

## 二、刷题本用户视角

> 画像：强化期在刷 1000 题，真题期开始上套卷，多科并行，想知道进度解读、套卷趋势、该不该切阶段、日量怎么调。

### 2.1 已实现且好用的功能

- **paper-trend 接口存在**（`ai.js:727` → `getPaperTrend`）：逐套输出 `{seq, date, score, sections:[{name,score,timeMin}]}`（`aiDataAggregator.js:344-367`），有/无 score 都有 hint 降级。
- **多科目 balance 接口存在**（`/api/ai/balance` → `getMultiSubjectBalance`），能按 gap 排出落后/超前名单（`aiDataAggregator.js:411-427`）。
- **今日时间 chips（F1.7）已落地**：输入框上方有 1h/2h/4h/全天（`index.html:2288-2294`），选中后写入 `state.budgetMin` 并随 chat context 带上（`app.js:16033`）。这是 v2 重点，做出来了。
- **adjust_daily_capacity / adjust_deadline / create_project** 这三个 op 在 `applyAction` 里有真实 store 写入（`app.js:15898-15925`）。
- **本地概览、单项目进度**（`getUserProfileSummary`/`getProgressSummary`）完成率、近 7 天速率、requiredRate、gap 都算了，口径清晰。

### 2.2 实现了但有问题的功能

1. **balance 只统计 exercise，背书积压和错题高危完全不参与"今天先救谁"**
   - `getMultiSubjectBalance` 里 `rows = list.filter(s => s.type==='exercise')`（`aiDataAggregator.js:414`）。
   - 后果：PRD §11.2 要的"全局时间守恒、此消彼长"是三科联动，现在退化成"只看刷题项目谁落后"。背书到期 100 条、错题 streaky 30 道，balance 里一个字都不提。
2. **ROI 排序是假的**：现在只是 `rows.sort((a,b)=>a.gap-b.gap)`（`aiDataAggregator.js:420`），没有 PRD §11.2.3 的分值权重（数学 150 > 英语/政治 100）、没有边际收益、没有紧迫度加权。
3. **`getTodayPlan` 里 recite 分支读了一个不存在的字段 `s.backlog`**
   - `aiDataAggregator.js:444`：`priority: s.backlog > 5 ? 'P0' : 'P1'`。
   - 但 `projectStats` 的 recite 分支（`aiDataAggregator.js:163-182`）**根本没算 backlog**（backlog 只在 `getReciteStatus` 里算）。结果 `s.backlog` 恒为 undefined，积压再多的背书也永远只排 P1，积压预警失效。
4. **estMin 估算是拍脑袋**：exercise 的 `estMin = minutesPerUnit * (gap<-40?8:4)`（`aiDataAggregator.js:458`），"8 页还是 4 页"与剩余工作量、deadline 完全脱钩；`minutesPerUnit` 取不到时用硬编码 7/3/5（`aiDataAggregator.js:440`），没有 PRD §4 的"从历史时间差滑动平均推断"。
5. **"全天"chip 名不副实**：`data-min="0"`（`index.html:2293`）→ `budgetMin=0` → 后端 `getTodayPlan` 把 `<=0` 一律当 240 分钟（`aiDataAggregator.js:434`）。点"全天"实际只排了 4 小时的量。
6. **时间守恒的"此消彼长"没做**：超前科不降速，落后科不主动加时，`allocatedMin` 经常远小于 `budgetMin` 却不解释剩下的时间去哪了（`aiDataAggregator.js:465`）。
7. **stage 阈值 `targetScoreTier` 读了等于没读**：`projectStats` 把它带出来了（`aiDataAggregator.js:148`），但 balance/today-plan/阶段切换逻辑里从没用到它做阈值分档（冲分 80%/稳分 70%/过线 60%）。

### 2.3 PRD 有但未实现的功能

- **阶段切换双向过渡 + 建套卷项目前查重**（§11.6、F5.3）：无对应逻辑、无对应 op。
- **`mark_units_optional`（砍范围）、`create_mock_paper_project`（建空套卷项目）、`compare_plans`（三方案对比卡）** 三个刷题评审重点 op：前端 `SUPPORTED_OPS` 全没有，`applyAction` 也没 case。CSS 里 `.ai-act-row.opt` 的样式钩子都写了（`app.js:15833`、`style.css:2185`），但 op 本身接不上——属于"样式留好了、功能没写"。
- **科目级热力图接口 `/subject-heatmap`**（§6.2）：后端路由表里没有。
- **时间成本接口 `/time-cost`**：没有。
- **效率推断 F7.2（刷题量 vs mastered 率背离识别灌水）**：没有。
- **主动触达隐性问题**（§11.5 新增 3 条）：前端 `pingRedDot`（`app.js:16253-16299`）只判断了"连续 3 天无打卡"和"deadline 7 天内且完成<30%"，**错题本连续 7 天无 review、稳定低产出 14 天、双刷题并行未达标、待复习逾期超阈值**这四条一个都没做。

### 2.4 具体改进建议

1. `getMultiSubjectBalance` 把 recite（dueToday/backlog）和 mistake（streakyCount）也纳入 rows，并按分值权重 + gap 重新打 ROI 分。
2. 修 `getTodayPlan` 的 `s.backlog` bug（在 `projectStats` recite 分支补算 backlog）。
3. 把"全天"chip 改成真实大预算（如 600min），或在 UI 标注"≈4h"。
4. 至少先把 `mark_units_optional` 和 `create_mock_paper_project` 两个 op 接上 store（CSS 钩子已就绪，成本低）。
5. 主动巡检补"错题本 7 天无 review"这一条——纯本地计数，性价比最高。

## 三、背书本用户视角

> 画像：手里 120+ 条待复习，冲刺期清不完，想要 AI 帮他"今天先清高危、按内容形态考我、别让我自欺、易混点别搞混"。

### 3.1 已实现且好用的功能

- **recite 状态聚合存在**（`/mistake-report` 之外，`getReciteStatus`，`aiDataAggregator.js:372-406`）：今日到期数 `dueToday`、逾期 `backlog`、掌握率、高危条目（上次结果是 forget/模糊的）top10 都算了。
- **`add_recite_items` op 有真实写入**（`app.js:15926-15940`）：能往背书项目批量加条目，初始化 learnedDate/reviews/mastered 字段齐全。
- 对话意图里有 `recite_help` 分支（`ai.js:126`），会把上面这份状态喂给 LLM 做"翻译成人话"。
- nextReviewDay 用 intervals 累加近似算下次到期日（`aiDataAggregator.js:123-131`），口径与 SRS 大体对齐。

### 3.2 实现了但有问题的功能

1. **「背书助手」本质只是"报数 + 让 LLM 随便说"，没有任何结构化出题能力**
   - PRD F4.2 要按 `item.form`（term/essay/composition/formula/discuss）自适应出题；现在后端聚合层**完全没读 item.form、points**，前端也没有任何遮罩/默写/抽点交互。
   - 用户问"帮我背书"，AI 只能回复一段"你今天有 12 条到期、8 条高危，建议先背这几条"的文字，**不能真的考他**。
2. **`add_recite_items` 写入的条目字段与主站 SRS 不完全对齐**：前端硬编码 `reviews:[{date, quality:3, stage:0}]`、`intervals` 等（`app.js:15932-15937`），但没写 `nextReviewDate`、`form`、`points`，与新数据模型脱节；且新条目的第一次复习被记成 quality=3，可能被 SRS 错误地拉长间隔。
3. **无"打开复习即遮罩答案"的交互**（F4.5）：这是 PRD 升 P0 的默认回忆流程，AI 面板里完全没有这层 UI。
4. **高危判定粗糙**：`highRisk` 只看"上一条 review 结果是不是 forget/模糊"（`aiDataAggregator.js:390-394`），不看连续模糊次数、不看间隔档位，无法支撑"易混对"识别。

### 3.3 PRD 有但未实现的功能

- **按 form 自适应出题**（F4.2）：挖空/采分点抽问/仿写批改/双向公式卡，全部未实现。
- **默认遮罩回忆 + 强制默写关键词 + 按点勾遗忘**（F4.5）：未实现。
- **易混点自动对比**（F4.3，升 P1）：基于"连续模糊 + 内容相似"自动识别易混对、推对比表、成对排期——聚合层和前端都没有。
- **积压减负 action**（F4.6）：`defer_low_risk_items`（顺延低危 1–2 天）、`compress_intervals`（考前压间隔）两个 op 既不在 `SUPPORTED_OPS`，也不在 `applyAction`。
- **新学窗口分级预警**（F4.4，肖四/时政破例）：未实现。
- **首页"今天先清这 N 条约 X 分钟、逾期折叠不堆红"**（F4.1）：现在只给总数 dueToday/backlog，没有折叠泄压。

### 3.4 具体改进建议

1. 背书是当前**最薄**的一块。短期最低成本：先把 `defer_low_risk_items` 接上（把选中低危 item 的 `learnedDate`/到期日顺延 1–2 天），让"积压减负"这个高频诉求至少有个出口。
2. `getReciteStatus` 增加"连续模糊次数"字段，为易混对识别留数据。
3. 中期再做按 form 的出题 UI——这是 M3 的事，但 PRD 把它列成了 P0，需要排期确认是否真的要在本期做。
4. 修 `add_recite_items` 的字段初始化，与主站 SRS 字段对齐。

## 四、汇总

### 4.1 总体评分：**4.5 / 10**

| 模块 | 得分 | 说明 |
|---|---|---|
| 错题本 | 5.0 | 有报告骨架，但聚类退化、建包 action 接不上、缺两类行为诊断 |
| 刷题本 | 4.5 | chips 和 paper-trend 不错，但 balance 只看 exercise、今日计划算法粗糙、核心砍范围 op 缺失 |
| 背书本 | 3.5 | 只有状态报数，PRD 升 P0 的"出题/遮罩/易混/减负"几乎全缺 |
| 基建（面板/配置/历史/样式） | 7.5 | 三 Tab、Key 加密、连通测试、用量条、深浅色、空态都做得干净，这部分是真能打的 |

扣分主因：M1（入口+算账）完成度尚可，但 **M2"能改数据"被 messageId bug 打断，M3"背书深度"基本没做**。

### 4.2 最严重的 3 个问题（必须修复）

1. **【P0·阻断】chat 不返回 assistant messageId → /apply 永远报"缺少 messageId" → 所有建议卡片本地改了数据却记录失败、撤销不可用、可重复点击造成重复写入。** 这是"AI 真改系统"这条命门，不修等于整个 AI 助手只是个聊天框。（`ai.js:501` 应返回 `messageId`；`app.js:16040` 接住；本地改动应在 /apply 成功后再落地，或失败时回滚 store。）
2. **【P0·功能缺失】PRD 三个高频场景 op 未接 store：`create_review_list`（错题建包）、`defer_low_risk_items`（背书减负）、`mark_units_optional`/`create_mock_paper_project`（刷题砍范围/建套卷）。** 前端 `SUPPORTED_OPS`（`app.js:15822`）只认 6 个 v1 op，PRD v2 扩的 9 个新 op 一个都没接。
3. **【P1·名不副实】错题"三维聚类"退化为 content 前 8 字分桶；背书"自适应出题/遮罩回忆/易混点"完全没做；balance 只看刷题不看背书/错题。** 三类用户各自的核心场景承诺都没有兑现到可用程度。

### 4.3 可以进入技术审查了吗？

**否。**

理由：
- 第 1 个问题是**运行时即现的阻断 bug**，不是风格问题——任何一个真实用户点一次"应用"就会踩中，且会造成数据被重复写入，属于"带伤上阵"。
- 第 2、3 个问题意味着 PRD v2 被评审点名要解决的场景深度（错题去数学偏科、背书减负、刷题砍范围）在代码里**基本没有闭环**，现在进技术审查，审完也只是一个"能聊天、能配置、但改不动数据、也不真懂你学习"的半成品。

**建议的放行门槛（修完再进技术审查）**：
